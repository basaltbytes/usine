# Persistence adapters

This inventory covers the persistence boundaries at commit `fbd379acb3b42f1868eb97c8cee0d6e39eac259c`, with the contract tests and dialect extraction in #896 and transcript sealing in #893. [ADR 0020](adr/0020-drizzle-portable-sqlite-projection.md#amendment-2026-11-03-896-sqlite-and-postgres-adapters) defines the dual-adapter decision.

## Runtime and configuration

Paths in this table are relative to the repository root. Engine services have declared interfaces in their corresponding `packages/engine/src/` modules. Their current `.layer` implementations require `RunDatabase`; none has a production memory adapter.

| Data and interface | Current adapter and location | SQLite dependencies |
| --- | --- | --- |
| Event ledger, claims, run lifecycle, attempts, approvals, results, salvage, failure resolutions, and CI waits: `RunStore` | `packages/engine/src/store/store.ts`, with focused queries in `store/` | Drizzle SQLite transactions, conflict handling and `RETURNING`; text JSON codecs; partial unique indexes for open attempts; foreign keys and checks. State predicates use the dialect's JSON extraction. |
| Run summaries, board history, evidence, worker counts, and sightings: `RunReader` | `packages/engine/src/run-reader/run-reader.ts`, `store/{queries,board,leftovers,loop-items}.ts` | JSON object and array aggregation, JSON array membership, numeric boolean predicates, rounded `julianday` durations, and JSON expression indexes. Evidence uses one read transaction. Window functions select current runs; the dialect module isolates SQLite expressions. |
| Transcript append and reads: `RunStore.appendTranscript`, `RunStore.transcript`, `RunReader.transcript`, and `RunReader.latestPoolRateLimits` | `packages/engine/src/store/transcript/{queries,segments,sealer}.ts`, `run-reader/run-reader.ts` | Global integer autoincrement sequence; unique attempt/direction/channel sequence; hot text JSON and sealed Brotli NDJSON segments; direction high-water marks for deduplication; snapshot reads that merge segments and late rows; generated JSON columns and a kind index; transactional upserts to the session-usage and pool-limit read models. The dialect module isolates JSON extraction. The startup migration backfills both read models with the previous grouping rules. |
| Item snapshots: `ItemProjectionReader`, `ItemProjectionWriter` | `packages/engine/src/item-projection/item-projection.ts` | Text JSON, JSON state extraction, null-safe `IS NOT` comparison, upsert with a conditional update, and revision triggers. |
| Repository label catalogs: `RepositoryLabelProjectionReader`, `RepositoryLabelProjectionWriter` | `packages/engine/src/repository-label-projection/repository-label-projection.ts` | Text JSON equality, conditional upsert, and revision triggers. |
| Cycle reservations, asks, reset answers, and pending cursor resets: `CycleBudgets`, with admission inside `RunStore` | `packages/engine/src/cycle-budget/` | Multi-table transactions, JSON state extraction, text-encoded asks, integer booleans, uniqueness, and revision triggers. |
| Operator dismissals: `AttentionAcknowledgements` | `packages/engine/src/attention/attention.ts` | Composite primary key, conflict-ignore insertion, JSON table expansion and extraction for pruning, and revision triggers. |
| Polling watermarks, ETags, schedule progress, and other replayable cursors: `CursorStore` | `packages/engine/src/cursor/cursor.ts` | Schema-encoded JSON text and upsert. Incompatible values log a warning and read as absent; storage failures remain errors. |
| Loop pause state: `LoopControl` | `packages/engine/src/loop-control/loop-control.ts` | Integer booleans and upsert. Missing state means unpaused. |
| Operator board-move attribution: `BoardMoves` | `packages/engine/src/board-moves/board-moves.ts` | Autoincrement tie-breaker, JSON label arrays, and timestamp ordering. Writes do not change the projection revision. |
| Configuration entities, role bindings, revisions, and revision streams: `ConfigurationStore` | `packages/config/src/configuration/{memory,sqlite/store}.ts` | Memory uses a `Ref`. SQLite uses `SqlClient`, `BEGIN IMMEDIATE`, upsert, JSON text values, a `sqlite-core` schema, embedded generated migrations, and the separate `usine_configuration_migrations` ledger. Revision streams read the revision log. |
| Members, hashed sessions, device tokens, and token scope ceilings: `AuthStore` | `apps/server/src/auth/{memory,sqlite}.ts` | Memory serializes mutations. SQLite uses `BEGIN IMMEDIATE`, `COLLATE NOCASE`, JSON extraction for member ordering, `json_set` for conditional token updates and scopes, `RETURNING`, and its own migration ledger. `MemberAccess` in `auth/access.ts` reads role bindings from `ConfigurationStore` and maintains the initial admin-binding migration in the separate `usine_access_migrations` ledger. OAuth state, setup challenges, and single-use links are intentionally ephemeral in `authentication.ts`. |

The runtime schema is `packages/engine/src/database/schema.ts`. Its SQLite-specific DDL includes `sqlite-core` column modes, autoincrement keys, JSON validity checks, expression and partial indexes, and revision triggers in generated migrations. `database/dialect.ts` contains all engine JSON function calls, duration arithmetic, null-safe comparison, numeric truth predicates, migration pragmas, and the legacy project migration's JSON and `instr` fragments. `database/local-sqlite.ts` owns the Node connection, statement-cache span isolation, migration execution, and online backup. `database/project-migration.ts` updates legacy loop references inside the caller's configuration transaction.

## Separate storage

| Data and boundary | Current implementation | Relationship to Postgres |
| --- | --- | --- |
| Parent tasks, conversation entries, durable documents, and submission deduplication: pi-durable `Storage`, opened through `DurableHarnessOptions.openStorage` | `packages/durable/src/harness.ts` injects storage; `live.ts` selects `openNodeSqliteStorage`. pi-durable owns the SQLite schema, migrations, WAL handling, and single-writer semantics. Its `MemoryStorage` is the reference adapter. | A separate database and transaction domain from the runtime store. A runtime Postgres adapter does not migrate parent storage. `packages/durable/src/backup.ts` uses Node's SQLite backup API. |
| Runtime and durable backups | `packages/engine/src/database/local-sqlite.ts`, `packages/durable/src/backup.ts`, composed by `apps/server/src/backup.ts` | Runtime `VACUUM INTO` omits free pages; the durable backup API preserves its online snapshot. Both include committed WAL data. Filesystem staging and hard-link publication prevent overwrites. Postgres needs its own backup and restore procedure. |
| Instance exclusion and process metadata | `apps/server/src/instance/{lock,record,id,manifest,ports,state}.ts` | The local instance lock uses a separate SQLite file, `BEGIN EXCLUSIVE`, `sqlite_master`, and `SQLITE_BUSY`. PID, manifest, port, and identity files use local filesystem operations. This is process exclusion for one instance folder, not a runtime persistence adapter or hosted tenant lock. |
| Local admin credential | `apps/server/src/auth/local.ts` | A token file in the instance directory, separate from hashed session and device-token records. No SQL dialect. |
| Configuration import and export: `ConfigurationFolder` | `packages/config/src/configuration/folder.ts` | YAML and Markdown files are interchange formats. `ConfigurationStore` remains the authority. No SQLite constructs. |
| Historical worker connections, known hosts, credentials, and provisioner start counts | Node worker adapters in `packages/executor/src/`, including `ssh/provisioner/starts.ts`; composition in `packages/orchestrator/src/{ssh,cloudflare,connections}.ts` | Local recovery records and files, separate from runtime rows. Preserve them for recovery and backups. No SQL dialect. |
| Gateway attachments: `Attachments` and `AttachmentPersistence` | `packages/gateway/src/attachment/` and `node/attachments.ts` | Memory mutations and serialized, encrypted, atomically replaced filesystem snapshots. Failed writes preserve memory. No SQLite constructs. |
| Cloudflare sandbox and sandbox-directory metadata: `SandboxStorage`, `RegistryStorage` | `packages/cloudflare/src/{sandbox/ports,registry,worker}.ts` | Durable Object key-value storage and alarms, with per-object serialization. No engine D1 adapter or SQL queries. These worker records remain separate from orchestrator state. |
| Run reader bookmarks | `apps/web` browser storage adapter | Bounded local browser metadata only; no transcripts or credentials. No SQL dialect. |

## Contract tests

`pnpm test` runs these suites in CI:

| Boundary | Registration and adapters | Required behavior |
| --- | --- | --- |
| Engine ports | `packages/engine/test/contracts/persistence.test.ts`; SQLite today | Each port has a contract function that receives a `PersistenceAdapter`. The fixture provides service layers, isolated storage, reopening, and write-failure injection without exposing a SQL client to the contracts. Tests cover rollback, deduplication, concurrent claims and appends, completion, ordering, board aggregation, cursor decoding, revisions, cycle resets, and transcript usage, worker, session, and pool reads. |
| Configuration entities and revisions | `packages/config/test/configuration.test.ts`; memory and SQLite | Atomic commits, rejected invalid and stale revisions, concurrent writers, entity order, normalized history, replay, and streams. Separate SQLite tests check cross-connection reads and reopening. |
| Auth and tokens | `apps/server/test/auth/store.test.ts`; memory and SQLite | Concurrent first enrollment, last-admin protection, member removal with credential revocation, case-insensitive identity, scoped token ownership, expiry, and conditional use updates. Separate SQLite tests check read behavior under a write lock. |
| Durable tasks and documents | `packages/durable/test/storage.test.ts`; pi-durable memory and Node SQLite | The pinned library's storage conformance suite checks atomic commits, ordered scans and pagination, document history, deduplication, isolation, and closure against both adapters. Harness and attempt-runtime tests separately check restart behavior. |

Add an engine adapter to the registration array and implement `PersistenceAdapter.fixture`; do not copy the contract assertions or replace them with SQL-specific expectations. The failure-injection service rejects an attempt insert or a run update and returns an effect that restores writes. Contract tests assert that partial state never becomes visible. SQLite migration, statement-retention, and `test/store/read-plans/` tests remain adapter-specific.

The transcript contracts run against the write-time usage and pool read models from #892 (implemented in #899). They assert the highest cumulative report per session, latest pool report across attempts, duplicate envelope retention, and latest lifecycle and worker notices beyond transcript pages. SQLite-specific parity, rollback, migration-backfill, and indexed-plan tests verify the projection implementation.
