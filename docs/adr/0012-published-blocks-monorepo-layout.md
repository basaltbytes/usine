# The engine ships as published blocks from a pnpm + turbo monorepo

usine is a monorepo in the manywalls/atoly shape — pnpm workspaces + turbo, `apps/` + `packages/`, shared tsconfig package, changesets, knip, renovate — and the engine's blocks are **published npm packages from day one**, at 0.x, under the `@usine` scope (claim the npm `usine` org first; `@usine-dev`, matching the domain, is the recorded fallback — the bare `usine` package name is squatted by an unrelated dead package). Nine packages publish, carved along the seams the map's decisions already drew: `core` (domain model — Event/Run/Step/Attempt — typed errors, ids, and the versioned attempt-channel envelope schema), `expression` (CEL check + eval seam), `loop-file` (loop/agent file schemas, frontmatter validation, surgical YAML-AST writer, instance-repo loader), `github` (polling change detection, per-stream GraphQL slice fetchers, App auth + token minting), `engine` (event ledger, dedup/supersede/revoke, run scheduling, durable-execution seam, SQLite store), `agents` (Pi parent adapter, subagents extension, roster + brain specs), `executor` (the scoped Worker contract, local + exe.dev executors), `orchestrator` (the embeddable composition), and `run-host` (the worker-side one-shot CLI — published because workers install it and preflight checks its version). `orchestrator` is a **library** exporting the full Effect-layer composition, startable in-process; `apps/server` is a thin CLI that runs it headless and serves `apps/web` (the web UI, internal, never published). Packages version **independently** via changesets — orchestrator↔run-host compatibility rides the envelope schema version ([ADR 0006](./0006-executor-contract-run-host-attempt-channel.md)), never matching version numbers. `effect` and the `@effect/*` packages each block uses are **peerDependencies** in every published package, exact-pinned once at the workspace root. v1 signs up for publish discipline — exports maps, no cross-package deep imports, a README per package — and explicitly not for API stability, a docs site, or support: 0.x is the honest contract while the APIs churn.

## Considered Options

- **Internal-only packages** — no publish machinery at all; rejected as contradicting the assemble-your-own-factory goal when changesets makes publishing nearly free.
- **Publishable shape, publish later** — same discipline, npm deferred until APIs settle; rejected because "later" reliably never comes and the scope sits unclaimed.
- **Coarser carve (4 packages)** — less version surface, but a third party takes the engine wholesale or not at all; the seams the map fought for would be invisible from outside.
- **Finer carve** — the surgical YAML writer, the Pi subagents extension, and GitHub App auth as their own packages; deferred until an outside consumer actually materializes — each stays a module inside its seam package, extractable later without breaking anyone.
- **App-only orchestrator** — simpler now, but the desktop all-in-one hope would then require carving a library out of an app under pressure.
- **Lockstep versioning** — "usine 0.4" as one number across everything; rejected as duplicating what the envelope version already guarantees, at the cost of empty bumps.

## Consequences

- **Revised 2026-08-21** (operator direction, implementation of [#24](https://github.com/basaltbytes/usine/issues/24)): the `loop-file` block is renamed **`config`** — the name describes the machinery (parse, validate, and surgically rewrite the instance repo's config files: `usine.yaml`, `loops/*.md`, `agents/*.md`) rather than one file kind it happens to parse. Contents unchanged; the carve stands.
- The post-v1 desktop hope stays additive: a shell wraps the served web UI, and an all-in-one app embeds `@usine/orchestrator` in-process — neither needs a new seam.
- **How `apps/server` ships** (npx, binary, container) is deliberately not decided here — it belongs to the distribution-and-bootstrap decision. **Settled by [ADR 0019](./0019-npm-instance-pinned-first-run-onboarding.md)**: `apps/server` publishes as `@usine/server` (bin `usine`, web build bundled), exact-pinned per instance by `create-usine`.
- Claiming the npm `usine` org is a first implementation act; if it's taken, everything above proceeds under `@usine-dev` unchanged.
- `core` carries the attempt-channel envelope schema so `run-host` never depends on orchestrator-side packages.
- Consumers of any published block must supply `effect` themselves at a compatible version — the peer-dependency posture trades install convenience for a single runtime in every tree.
- **Revised 2026-09-05**: public subpaths describe capabilities independently of source layout: `/polling` maps to `polling/polling.ts`, and `/operator` provides the operator contracts and implementation. Entry modules explicitly select same-package exports, so a source-level helper does not automatically become part of the published interface. Workflow commands and content-hash bookkeeping remain package implementation details. Consumers import shared domain definitions from their owning package rather than through aliases. Core identities are defined beside their records and operations; related domain modules use folders (`run/`, `step/`, `attempt/`, `agent/`). Node adapters retain separate entry points, including independently composable Pi parent and harness child layers as well as the assembled agent runtime.
- **Amended 2026-09-01** (implementation of [#31](https://github.com/basaltbytes/usine/issues/31)): the peer-dependency rule applies to the published **libraries**. `@usine/server` is an application (bin `usine`, installed per instance by `create-usine`), so it carries `effect` and `@effect/platform-node` as ordinary dependencies — an app must be runnable from a plain install with no host-supplied runtime.
- **Amended 2026-10-11** ([#176](https://github.com/basaltbytes/usine/issues/176)): `run-host` is deleted, and `durable` (the Pi parent as a pi-durable task) publishes instead. Every Attempt's Pi parent runs in the orchestrator, and Workers only run its children, so no usine package is installed on a Worker and preflight checks no usine version there. `agents` keeps the child backends, prompts, and preflight; its Pi parent layer and the assembled agent runtime went with the run host, their only caller. `core` keeps the versioned envelope schema, which the durable relay writes and the transcript store reads.
- **Amended 2026-10-18** ([#310](https://github.com/basaltbytes/usine/issues/310), [#233](https://github.com/basaltbytes/usine/issues/233)): `gateway` publishes too. The executor imports its admin contract from `@usine/gateway/admin`, so the published executor cannot install without it, and a gateway host installs the service from npm rather than from tarballs packed in a checkout. The package holds no secret: the gateway reads its tokens and keys from the environment. Every published package that depends on `@effect/platform-node` also depends on `@effect/platform-node-shared` at the catalog version. `@effect/platform-node` asks for it with a caret range, which npm and pnpm otherwise resolve to the newest stable release, and that release needs a newer `effect` than the catalog pins.
