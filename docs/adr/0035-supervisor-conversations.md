# Supervisor conversations

A conversation is a record in the runtime database behind the `ConversationStore` port. It has messages, turns, and the session events of each turn, numbered in one sequence per conversation, so a client reads new events with a cursor. The harness's own saved session is a file in the conversation's directory; usine stores only the reference that the next turn reopens.

An anchor is a kind, a reference, and a key that is the SHA-256 of both. usine doesn't interpret the kind or the reference, so a caller such as the walkthrough can anchor conversations to things that usine doesn't model, and look them up by key.

One turn runs at a time per conversation, in message order, so a message posted during a turn queues behind it. At startup, a turn that was running is `failed` with an interrupted marker, because its session process ended with the old orchestrator and not every harness can resume in the middle of a tool call. Its events and usage stay, and queued turns run.

A supervisor turn is read-only: it has `read` on the conversation's scope, within the current permissions and operation ceiling of the credential that posted its message, and can't call an operation that needs more or any conversation route. usine recomputes this at every request, so a revoked token ends the turn's access, and a queued turn fails when its token was revoked or its member lost `operate` on the scope. Changing the factory from a conversation needs a member's confirmation, which turns don't have, and read-only turns show a project's readers nothing they can't already read.

The harness's session files live in a preallocated ext4 image per conversation, mounted with FUSE on the orchestrator host. Containers and Pi's host-side writes use the same filesystem, so every writer has one capacity limit. Container storage-driver quotas don't bound host-side writes to a bind mount, and measuring a directory now and then can't stop a fast writer before it fills the instance disk. The image can't grow, so a full filesystem returns a no-space error. This needs Linux, FUSE, and filesystem tools on the host, and reserves the configured size for each saved conversation; an unavailable mount refuses the turn. Resizing an image needs an offline migration. Turns, shutdown, and startup remove containers by label before unmounting, and an earlier container blocks another turn on the same conversation.
