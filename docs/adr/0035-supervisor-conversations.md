# Supervisor conversations

A conversation is a record in the runtime database behind the `ConversationStore` port. It has messages, turns, and the session events of each turn, numbered in one sequence per conversation, so a client reads new events with a cursor. The harness's own saved session is in the conversation's saved home; usine stores only the reference that the next turn reopens.

An anchor is a kind, a reference, and a key that is the SHA-256 of both. usine doesn't interpret the kind or the reference, so a caller such as the walkthrough can anchor conversations to things that usine doesn't model, and look them up by key.

One turn runs at a time per conversation, in message order, so a message posted during a turn queues behind it. At startup, a turn that was running is `failed` with an interrupted marker, because its session process ended with the old orchestrator and not every harness can resume in the middle of a tool call. Its events and usage stay, and queued turns run.

A supervisor turn's credential is read-only: it has `read` on the conversation's scope, within the current permissions and operation ceiling of the credential that posted its message, and can't call an operation that needs more or any conversation route. usine recomputes this at every request, so a revoked token ends the turn's access, and a queued turn fails when its token was revoked or its member lost `operate` on the scope. Read-only turns show a project's readers nothing they can't already read. The turn's other operator calls become permission requests ([ADR 0036](./0036-supervisor-permission-requests.md)).

The harness's home is a size-limited tmpfs in the turn's container. usine keeps each conversation's saved home on the orchestrator as an archive, copies it in before the harness starts, and copies it out when the turn ends, stopping at the size limit. The kernel bounds the container's writes and only usine writes to the host disk, so no host privilege is needed. The earlier ext4 image, mounted with FUSE, needed the setuid `fusermount3`, which the documented unit's `NoNewPrivileges=yes` blocks. The tmpfs counts against the container's memory. A crash during a turn loses that turn's home changes. Pi writes its session files from the orchestrator, and usine checks their size before and after each turn.
