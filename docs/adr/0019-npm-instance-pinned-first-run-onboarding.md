# usine ships on npm, pinned per instance; the factory is born in the first-run web UI

v1 distributes exactly one way: **npm**. `apps/server` is promoted to a published package — **`@usine/server`**, bin **`usine`** — a thin CLI over `@usine/orchestrator` that bundles the built web UI as static assets (the `apps/web` source stays unpublished; ADR 0012 amended). An instance is born with **`pnpm create usine`** (published as `create-usine`): it scaffolds the instance folder — invisible local `git init` ([ADR 0009](./0009-instance-repo-remote-optional-runtime-state.md)), a `usine.yaml` skeleton (config schema `version:`, empty registry, implicit local worker, `webhooks.mode: off`), empty `loops/` and `agents/`, a `.gitignore` covering `.usine/` and `node_modules/`, and a **`package.json` + lockfile exact-pinning `@usine/server`** — installs, and makes the initial commit. The pin is the point: the engine version is **per-instance, committed, authored config** — upgrading is editing the pin and restarting, forward-only SQLite migrations run at startup (backup = stop + copy the folder, [ADR 0010](./0010-single-sqlite-runtime-store.md)), and sharing the instance repo (ADR 0009's sharing story) now reproduces the exact factory, engine included. No example loop or agent is scaffolded — git-born loops arm immediately ([ADR 0016](./0016-config-editing-forms-first-preview-before-arming.md)) and cold start fires on existing state ([ADR 0007](./0007-polling-triggers-content-hashed-events.md)), so a demo loop would act on real repos; the first loop and agent are born in the UI, paused. Day to day the orchestrator is a **foreground CLI**: `usine up` from the instance folder resolves the local install, prints the UI URL, and opens the browser on first run; keeping it alive (tmux, launchd, systemd) is the operator's business with copy-paste docs, and service management, Docker, and a standalone binary all stay additive. **Bootstrap lives in the first-run web UI**: `up` with no App credentials starts in a needs-setup state (pollers idle) and the UI walks the ceremony — manifest-flow App creation against the orchestrator's own redirect endpoint (permissions per [ADR 0011](./0011-github-app-identity-scoped-worker-tokens.md); `hook_attributes` active with the placeholder `.invalid` URL and the generous event set per [ADR 0014](./0014-webhook-delivery-as-hints.md)), the conversion response captured into the 0600 `.usine/` secrets file (App id, private key, webhook secret; env override), the operator's GitHub login prefilled from the flow into `usine.yaml` ([ADR 0017](./0017-away-intervention-github-native-asks.md)), installation on the managed repos, then the installation-bound add-repo picker (ADR 0016) filling the registry. Worker-readiness guidance is the **UI preflight surface**: the Workers page under Configuration runs [ADR 0006](./0006-executor-contract-run-host-attempt-channel.md)'s verify-only preflight on demand and renders each typed capability error with its remediation text (e.g. "run `claude /login` in a terminal"); interactive harness logins stay in the operator's own terminal. The CLI surface is two acts: `pnpm create usine` and `usine up`.

## Considered Options

- **Global tool** — engine installed once per machine (or dlx'd), instance folders pure config. Rejected: every factory on the machine upgrades at once, forward-only migrations make an accidental upgrade a one-way door, and a shared instance repo no longer says what runs it.
- **Standalone binary / Docker-first** — zero-prereq and clean-isolation stories. Rejected for v1: the harnesses are npm CLIs, so the local worker needs Node regardless, and a containerized orchestrator fights the same-machine local worker (host toolchain, worktrees, harness logins). Both stay additive forms — Docker likely first when the orchestrator moves to the cloud.
- **CLI wizard ceremony** — `init` opens a browser and runs a temporary localhost server for the manifest redirect. Rejected: it duplicates the HTTP server the orchestrator already is, and the add-repo picker lives in the UI anyway.
- **`usine doctor`** — a terminal check-and-explain command. Rejected for v1: it would re-render the same typed preflight errors the Workers page shows; additive if terminal-first demand appears.
- **Scaffolded example loop/agent** — a friendlier first five minutes. Rejected: git-born loops are born armed and cold start fires on existing state — a demo loop would act on the operator's real repos.

## Consequences

- ADR 0012 amended: `@usine/server` joins the published set (bin `usine`, bundled web assets); `create-usine` publishes alongside as the scaffolder, not a block. The `@usine-dev` fallback posture is unaffected — `create-usine` is unscoped and free either way.
- The instance repo is now a Node package: `package.json` and its lockfile are authored config and commit; `node_modules/` joins `.usine/` as gitignored runtime. UI config commits (ADR 0009) never touch the pin — upgrading is an operator act.
- Onboarding must be resumable: each ceremony step is idempotent and independently re-enterable (App created but key lost, key present but nothing installed, installation live but registry empty) because a first run can die anywhere.
- Locally, orchestrator↔run-host version skew is impossible — one install carries both; skew stays a remote-worker concern surfacing at preflight (ADR 0006).
- The exe.dev baked image stays adapter-owned readiness (ADR 0006) — nothing here ships it.
