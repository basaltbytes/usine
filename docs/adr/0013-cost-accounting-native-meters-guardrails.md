# Cost accounting: native meters per pool, guardrails not budgets

v1 meters everything and enforces no dollar budget. Every attempt's usage rides the attempt channel's normalized event stream and lands as a summary on the Attempt row — per child: harness, model, tokens (in/out/cache read/cache write), and USD where a real or estimable rate exists. Each **pool** — the billing source, not the harness — keeps its native meter: **API keys** (Pi parent and Pi children; Pi reports USD per message), **Claude plan** (Claude Code children; self-metered estimated USD via the Agent SDK's `modelUsage`, flagged as estimate), **ChatGPT plan** (Codex children; tokens plus rate-window percentages from app-server snapshots). No fabricated conversions: a pool without a dollar rate is never shown in dollars. The only hard limits are guardrails where runaway actually happens: a per-Attempt **child-session budget** and a per-attempt **runaway guard** (wall-clock + total-token ceilings). Crossing either limit fails the Attempt with a typed error that never auto-retries.

## Considered Options

- **Enforced dollar budgets** (monthly ceilings per loop/factory, engine stops opening runs) — rejected for v1: two of three pools have no dollar meter usine controls, the Claude figure is a client-side estimate from a bundled price table (not billing truth), and approval gates + worker concurrency caps already throttle volume. The attempt rows hold everything a later budget layer needs.
- **Dollars everywhere** (estimated USD as the one unit, Codex dollarized at API-equivalent rates) — one comparable number per run, but a partly fictional one; rejected for native meters.
- **Engine reacts to pool exhaustion** (hold attempts until the window resets) — kinder to retries but adds scheduler machinery and a second "why isn't my run starting"; rejected for display-only pool health.
- **Accounting only, no guards** — a runaway agent inside one attempt burns until the provider cuts it off; rejected.

## Consequences

- **Revises [ADR 0005](./0005-pi-parent-agent-layer-team-roster.md)**: the announced monthly Agent SDK credit was paused before taking effect — Agent SDK usage draws from the subscription's ordinary usage windows, and no official API exposes plan balance or usage. The Claude pool's meter is therefore self-metered estimated USD, not a credit balance; opportunistic signals (rate-limit response headers, the undocumented OAuth usage endpoint) are display hints at best, never load-bearing.
- Usage facts are attempt-channel envelopes: the run drawer shows live running totals from the stream; the Attempt-row summary is written at attempt end. Rollups — per run, loop, project, pool; calendar month — are queries over Attempt rows (ADR 0010 prunes nothing), no separate ledger.
- Guard knobs live in `usine.yaml` settings: `max_children` (total child sessions spawned per Attempt, default 4), `max_attempt_minutes` (default 60), `max_attempt_tokens` (parent + children total, default 10M). Each accepted spawn logs its cumulative count and a bounded task excerpt. When the count exceeds `max_children`, the engine stops the parent and records `ChildSessionBudgetFailure`; the drawer and needs-you strip show the configured and attempted counts. The runaway guard meters orchestrator-side from channel events and trips via the existing two-stage interrupt (ADR 0006); its typed failure remains distinct from infra errors, so ADR 0002's auto-retry never applies.
- Pool health is display + warn: the latest snapshot per pool persists (Codex pushes window snapshots during runs; on-demand read exists); the Usage page under Configuration shows the three meters, and the needs-you strip warns past a threshold (default 80% of the Codex window). Scheduling never consults pool health — an exhausted-pool attempt fails typed with the window's reset time visible.
- UI surface: a per-run cost line (per pool, per child) in the run drawer, plus one Usage page — current-month rollups per loop and per pool, no charts. Trends and per-agent breakdowns stay out of v1.
- Per-harness native caps (e.g. the Claude SDK's `maxBudgetUsd`) remain adapter-internal defense-in-depth, additive behind the seam — never the operator-facing guard.
