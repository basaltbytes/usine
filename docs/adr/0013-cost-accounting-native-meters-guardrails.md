# Cost accounting: native meters per pool, guardrails not budgets

v1 meters everything and enforces no dollar budget. Every attempt's usage rides the attempt channel's normalized event stream and lands as a summary on the Attempt row — per child: harness, model, tokens (in/out/cache read/cache write), and USD where a real or estimable rate exists. Each **pool** — the billing source, not the harness — keeps its native meter: **API keys** (Pi parent and Pi children; Pi reports USD per message), **Claude plan** (Claude Code children; self-metered estimated USD via the Agent SDK's `modelUsage`, flagged as estimate), **ChatGPT plan** (Codex children; tokens plus rate-window percentages from app-server snapshots). No fabricated conversions: a pool without a dollar rate is never shown in dollars. The only hard limits are guardrails where runaway actually happens: a per-Attempt **child-session budget** and a per-attempt **runaway guard** (wall-clock + total-token ceilings). Crossing either limit fails the Attempt with a typed error that never auto-retries.

## Considered Options

- **Enforced dollar budgets** (monthly ceilings per loop/factory, engine stops opening runs) — rejected for v1: two of three pools have no dollar meter usine controls, the Claude figure is a client-side estimate from a bundled price table (not billing truth), and approval gates + worker concurrency caps already throttle volume. The attempt rows hold everything a later budget layer needs.
- **Dollars everywhere** (estimated USD as the one unit, Codex dollarized at API-equivalent rates) — one comparable number per run, but a partly fictional one; rejected for native meters.
- **Engine reacts to pool exhaustion** (hold attempts until the window resets) — kinder to retries but adds scheduler machinery and a second "why isn't my run starting"; rejected for display-only pool health.
- **Accounting only, no guards** — a runaway agent inside one attempt burns until the provider cuts it off; rejected.

## Consequences

- **Revises [ADR 0005](./0005-pi-parent-agent-layer-team-roster.md)**: the announced monthly Agent SDK credit was paused before taking effect — Agent SDK usage draws from the subscription's ordinary usage windows, and no official API exposes plan balance or usage. The Claude pool's meter is therefore self-metered estimated USD, not a credit balance; opportunistic signals (rate-limit response headers, the undocumented OAuth usage endpoint) are display hints at best, never load-bearing.
- Usage facts are attempt-channel envelopes: the run drawer shows live running totals from the stream; the Attempt-row summary is written at attempt end. Rollups — per run, loop, project, pool; calendar month — are queries over Attempt rows (ADR 0010 prunes nothing), no separate ledger.
- Guard knobs live in `usine.yaml` settings: `max_children` (total child sessions spawned per Attempt, default 4 — this supersedes the earlier concurrent-children reading inherited from the davis extension's cap), `max_attempt_minutes` (default 60), `max_attempt_tokens` (parent + children total, default 10M). Each accepted spawn logs its cumulative count and a bounded task excerpt. When the count exceeds `max_children`, the run host's Pi parent rejects the spawn and stops its own session with a typed error; the engine records it as `ChildSessionBudgetFailure`, and the drawer and needs-you strip show the configured and attempted counts. The runaway guard meters orchestrator-side from channel events and trips via the existing two-stage interrupt (ADR 0006); its typed failure remains distinct from infra errors, so ADR 0002's auto-retry never applies.
- Pool health is display + warn: the latest snapshot per pool persists (Codex pushes window snapshots during runs; on-demand read exists); the Usage page under Configuration shows the three meters, and the needs-you strip warns past a threshold (default 80% of the Codex window). Scheduling never consults pool health — an exhausted-pool attempt fails typed with the window's reset time visible.
- UI surface: a per-run cost line (per pool, per child) in the run drawer, plus one Usage page — current-month rollups per loop and per pool, no charts. Trends and per-agent breakdowns stay out of v1.
- Per-harness native caps (e.g. the Claude SDK's `maxBudgetUsd`) remain adapter-internal defense-in-depth, additive behind the seam — never the operator-facing guard.

[ADR 0022](./0022-item-cycle-budgets-and-comment-reviews.md) extends this decision with durable Item cycle budgets, operator reset Asks, and comment-only reviews under the shared App identity.

## Amendment (2026-09-18): opt-in ceilings, an honest meter, and salvage before cleanup

The runaway ceilings are now opt-in: `max_attempt_minutes` and `max_attempt_tokens` have no default, and an absent setting leaves that half of the guard unarmed. The old defaults (60 minutes, 10M tokens) were chosen before real Attempts ran; legitimate work on a large issue takes two or three hours, and a tripped guard used to remove the worktree with the finished work still in it (issue #161). An operator who wants a ceiling sets one, and an armed ceiling now sends the parent session one steer at 80% of its limit so the agent can commit and push before the trip.

The token meter changed with it. The guard summed each harness's cumulative total, which for Codex and Claude includes the whole context re-read on every turn, cached or not, so the count grew with conversation length rather than with work: a healthy Codex Attempt reached 2M "tokens" in five minutes. `TokenCount` now means output tokens plus uncached input (new prompt text and cache writes), computed per harness from the fields each SDK reports separately. It still feeds the Attempt row and the drawer whether or not a ceiling is armed.

Independently of the guard, every Attempt that ends without a `Succeeded` outcome now salvages its worktree before cleanup: uncommitted changes become a `wip(usine): salvage attempt <id>` commit and HEAD is pushed to `usine/salvage/<run>/<attempt>`, recorded on the Attempt and checked out by the next retry. A failed push keeps the worktree on the Worker and records its path instead.

## Amendment (2026-10-18, #282): a retry applies the salvage onto the current revision

Checking the salvage out as it was kept every retry on the base of the first Attempt. For an issue Run the revision is the default branch tip at each fetch, so a fix merged after the first Attempt never reached the retries, and an Attempt that changed nothing pushed the same old salvage again for the next one. A retry now fetches the revision again and rebases the salvage's own commits onto it. A salvage with no changes beyond the revision is dropped. A salvage that does not rebase cleanly is left out rather than merged with conflict markers: the Attempt starts from the revision, its prompt and the transcript's `Started` envelope name the salvage, and the salvage branch keeps the work for the agent or the operator to reuse.

## Amendment (2026-10-19, #324, #266): lost connectivity is a signal with no default ceiling

On 2026-10-15 a Worker accepted TCP but sent no SSH banner for over ten minutes, and a Codex child reported `Reconnecting... waiting for network` every 90 seconds for 40 minutes. Neither Attempt failed or said anything; the operator found both by reading harness output by hand. A Worker that stops answering, or a harness that cannot reach its model provider, can recover on its own, and the work done so far is in the Worker's checkout, which an Attempt failed while the Worker is silent could not salvage. So connectivity loss gets the same treatment as the runaway ceilings above: no default limit, and nothing stops or fails the Attempt on it. What changed is that the operator can see it, in the Attempt's transcript and in the logs, with the time it began, and decide whether to wait, steer, or cancel.

The executor finds out that a Worker stopped answering by running `true` on it over a new SSH connection every minute while an Attempt runs there. Nothing else reaches the Worker at a useful interval during an Attempt: the children's SSH sessions are long-lived, and their keepalives did not end them on 2026-10-15 while no new connection got a banner; the executor's own commands run at cleanup, at the end, or when a credential nears expiry. The harnesses report their own provider retries, so the children's adapters pass those on as they arrive instead of measuring anything themselves.

## Amendment (2026-10-22, #248): a Gateway's API key puts Claude Code children in the API keys pool

The decision above puts Claude Code children in the Claude plan pool unconditionally. A Worker behind a Gateway that holds the Anthropic credential (`llm_providers: [anthropic]`, [ADR 0027](./0027-gateway-credential-proxy.md)) sends its Claude Code children's requests with the Gateway's credential, which is either an API key (`ANTHROPIC_API_KEY`) or a subscription token. Children paid with the API key were reported in the Claude plan pool with an estimated figure, although the key is billed at the model's API rate.

A pool is the credential that pays, not the harness ([ADR 0021](./0021-pi-parent-pool-follows-authentication.md)). A Claude Code child that a Gateway pays for with an API key is therefore in the API keys pool, and the Agent SDK's figure for it is shown as its price at the model's rate, without the estimate mark. Every other Claude Code child stays in the Claude plan pool: one on a Worker without a Gateway, one that uses its login on the Worker, and one that the Gateway pays for with a subscription token.

The Gateway reports the kind of credential it holds for each LLM provider on its admin API (`GET /v1/providers`, `api-key` or `subscription`). `usine.yaml` has no field for it, because only the Gateway knows which credential it holds. The executor reads the kind at the preflight of each Worker whose `llm_providers` lists `anthropic` and records it with the Worker. Each child session records the kind that paid for it (`ChildSession.gatewayCredential`), so a later change of the Gateway's credential leaves the pool of earlier sessions as it was. A Gateway that holds no Anthropic credential while the Worker's `llm_providers` lists it fails the preflight, because it refuses every Claude Code request. A Gateway released before the endpoint answers 404, and its Workers keep the Claude plan pool, with a warning at each Worker's preflight.

The kind is read at preflight, not for each Attempt. A Gateway reload that replaces the API key with a subscription token, or the reverse, applies to new sessions after the Worker's next preflight: when the orchestrator starts, or when a configuration reload adds the Worker, gives it more slots, or adds a brain to the roster. Each child session takes the Worker's recorded kind when the child starts, so the next child of an Attempt that is already running records the new kind.
