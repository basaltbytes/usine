# Web change notices and scoped reads

The web app uses one authenticated server-sent events connection for invalidation. Notices contain entity identifiers and a monotonically increasing revision. The browser reads the affected projections through TanStack Query; notices contain no entity payloads.

Committed writes publish scoped change targets to one in-process Effect `PubSub`. Engine transactions collect and deduplicate their run, attempt, item, and cycle-budget targets, then publish after commit. Item projection updates publish only when stored content changes. Configuration application, attention dismissals, worker preflight and slot changes, machine state, upgrade state, transcript appends, and poll completion publish from their write paths. Standalone blocks use an optional observation service; the server provides one bus for its entire lifetime, including setup and runtime activation.

The SSE handler computes no read projections. It resolves repository and loop ownership from current configuration and filters notices by the subscriber's permissions before serializing identifiers. Global configuration changes invalidate readers. Worker and upgrade status identifiers require instance access. Machine transitions also publish run notices scoped to the run’s loop; provisioning pauses publish run and item notices for leases on the affected worker. Changes to upgrade admission invalidate shared configuration without exposing run identifiers. Each authorized notice includes the dependent project, navigation, attention, and activity targets needed to refresh those views.

One journal retains the latest 256 notices with monotonically increasing revisions. A subscription starts before the replay snapshot is read, so writes cannot be lost between replay and live delivery. Reconnects use `Last-Event-ID`; a missing, expired, invalid, or future cursor receives a reset notice. A slow subscriber whose bounded queue drops notices also receives a reset. A reset invalidates active reads. The server revalidates credentials before delivery and at each 15-second heartbeat. The bus and journal end when the server stops.

Elapsed times derive from timestamps in the browser. Known attention deadlines, such as webhook silence and pool resets, schedule one notice at the deadline without computing projections. Startup restores future pool reset deadlines from each pool’s latest persisted report; expired and superseded reports schedule no notices. Poll completion publishes attention notices when failures or preflight findings change. Unchanged polls publish no notices, so idle boards keep their cached activity reads. Poll completion timestamps refresh on the next state change or manual refresh.

Navigation and attention reads omit board payloads. Navigation retains compact task identities for headings and notifications. Project reads supply boards. Settled lanes load cards in pages of 50; task run history loads in pages of 25. Both lists virtualize long histories. Command search loads its searchable projection when opened. Route loaders prefetch screen data, and intent preloading fetches task and run links on hover or focus.

Successful JSON reads have private ETags. Authorization precedes conditional response handling, and validators vary by browser credentials and read representation. Browsers revalidate cached reads without transferring an unchanged body. The stream disables caching and proxy buffering.

Task detail and history queries refresh when any item in their latest fetched membership changes. Connected screens have no interval polling. Members without read access refresh their session every 60 seconds until a role binding grants access and the shell opens its connection. During disconnection, one app-wide timer invalidates active reads every 60 seconds. The refresh indicator reports disconnection. Board mutations add optimistic move state in `onMutate`, remove it on failure, and retain accepted moves until a changed project projection confirms GitHub state.
