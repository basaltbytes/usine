# Durable CI waits

A developer or fix attempt can end its session after pushing while the run remains open in `AwaitingCi`. The engine stores the pull request number, exact head, fix loop, timeout, and label actions with the run, ends the attempt window, and releases its worker slot. Polling and repository hints reconcile the stored waits without starting a model or reserving a worker; startup excludes these runs from driving fibers and recovers their checkouts as finished work.

A loop's optional `ci` policy is captured with the trigger event, so a configuration edit cannot remove the requirement from an existing run. An ordinary successful answer from a configured loop still waits for the harvested pull request head. Explicit handoffs must match a harvested pull request and its pushed head; malformed or unverified handoffs fail. The configured fix loop and timeout override values in the answer. Completion actions are label additions and removals on items in the same repository, which can be retried safely after a partial write or restart.

Only GitHub's successful aggregate for the recorded head allows completion actions and success. Missing checks remain pending. Failed checks submit one event to the configured, active PR fix loop with failed job names and at most 12,000 characters of log evidence. The event uses the source run and head as its dedup key and enters ordinary cycle-budget admission, approval, and scheduling. A persisted `ciFailureHead` distinguishes these events from label trigger matches: a queued fix rechecks that the PR remains open at that failing head, rather than requiring the label condition again. Submission precedes settlement so a restart between them repeats the same event. Exhausted budgets retain their ordinary operator ask.

A newer PR head cancels the wait without applying its actions, an extension to the supersession rules in ADR 0007 after the attempt has ended. A timeout fails the attempt and run into Needs attention. Settlement checks the waiting state and expected head in one database transaction, preserving the session end time; late observations cannot change a settled or canceled run. GitHub label writes precede local success and may repeat if the process stops between them. GitHub cannot atomically compare a head and mutate labels; the monitor checks the current head before applying actions.

The run page and board show **Waiting for CI** with a link to the PR checks. Review loops can omit `ci` and finish at the end of their session. This replaces agent-side CI watches for configured developer and fix loops while retaining ordinary session completion for other loops.
