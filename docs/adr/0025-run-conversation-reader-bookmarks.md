# Run conversation reader bookmarks are stored in the browser

The run drawer restores a reader's conversation filter, disclosures, and reading position after closing or refreshing. As one browser's choices, they're stored in the browser per run, not in the transcript or the operator API.

The TanStack Query cache still has the fetched pages: closing the drawer reuses them, and a refresh starts at the newest page, fetching earlier ones through the existing mutation. The projection's attempt, session, and call identities identify tool rows, and transcript sequences identify notices. A bookmark stores one identity, its surface (row, completed group, or result), and its viewport offset. Completed-group bookmarks reference an original member, so earlier insertions don't break them. The disclosure map supplies explicit choices; automatic reveals share its reducer without posing as navigation.

Restoration pauses `MessageScroller`'s following, opens the needed disclosures, waits for layout, and navigates through its public API, plus a second animation frame for scrollability. `PreserveReadingPosition` then resumes, keeping context through updates. Explicit navigation cancels recovery. Automatic history recovery stops at 20 pages; missing rows, failed requests, and that limit yield an explained nearest row without acknowledging unread activity.

Unread activity uses the last acknowledged raw transcript sequence. The row index deduplicates starts and results, and rebuilding from that checkpoint finds unread rows on earlier pages after a refresh. Reopening at an anchor can't acknowledge new updates; following the latest in Everything, or a jump to the latest, does. Filtered views and error navigation leave them unread.

No browser-persistence adapter existed. The storage boundary uses the pinned Effect Schema decoder, accepts only versioned, bounded metadata, and handles inaccessible or full storage with a safe diagnostic. It keeps at most 20 runs for 30 days, 200 recent disclosure choices per run, and 512,000 serialized characters. Scrolling captures the row at once and debounces writes, which closing the drawer, leaving the page, and backgrounding flush. Invalid or obsolete bookmarks use defaults; transcripts and tool payloads are never stored.

## Amendment (2026-10-20, #403): the outline folds turns; the error count shows what needs reading

The outline listed each attempt message by first sentence under its session, so forty turns meant forty truncated sentences burying the checkpoints (a blocker, a question, an operator message, a worker that stopped answering, the outcome) among progress notes. It now lists an attempt's checkpoints on one rail in conversation order. Consecutive turns of one session fold into one entry with the session name and a count, which opens to the sentences on request. Other checkpoints stay separate. The reading mark is on a closed fold, or on its sentence once open. Folds open only on request (auto-opening the one being read would restore the long list) and reset with the page, unbookmarked.

The red count included every errored tool call, but agents routinely run failing commands and continue, so successful runs showed "18 errors" and looked broken. It now counts only what the run ended with or the operator must read: each failed attempt's outcome (the last being the run's failure), every blocker and question, operator input a session refused, and connectivity warnings still open on a running attempt. A tool call that failed while its attempt continued goes to a quieter "recovered" count with its own navigation. A failed call the attempt didn't continue from isn't recovered: the attempt's outcome covers it.
