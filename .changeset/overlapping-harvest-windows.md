`harvestFacts` and `harvestPostedComments` leave out a comment or review posted while another Attempt of the same Agent was open on the Run's Item. Two Loops' Runs of one Agent on one pull request write as one bot login and sign alike, so such a comment could be either Attempt's, and neither records it. Each one left out gets an info log line that names the comment and both Attempts, and the harvest's summary line counts them as `ambiguous`. They also leave out a comment posted after the Attempt's own window ended. A canceled Attempt's window ends before its executor stops and harvests it, and an Attempt of the Agent that starts after that end does not overlap it. Each such comment gets an info log line with the Attempt's window, and the summary line counts them as `outside`. A comment counts from its creation and a review from its submission, so a comment the bot login posted before the Worker prepared the checkout and edited since is no longer recorded; the summary line counts those as `edited`.

`@usine/core`: `@usine/core/attempt` exports `AttemptWindow`, the time an Attempt was at work on its Item according to its record, with `windowOf`, `windowHolds`, and `windowsOverlap`. The Run reader and the harvest both apply this rule. `AttemptWindows` holds an Attempt's own window (`own`) and the windows of the Agent's other Attempts that overlap it on the Item (`overlapping`). `harvestFacts` and `harvestPostedComments` take `windows`, an `AttemptWindowsRead` of them, and run it once GitHub has listed the comments. When it fails, `harvestFacts` fails with a `HarvestError` at the new `windows` stage, and `harvestPostedComments` records no comment. `AttemptChannel.Sink` and `RecoverySink` have `windows`, which reads them.

`@usine/engine`: the sink a Run's fiber passes to `StepExecutor.execute`, and the `RecoverySink` that startup reconciliation passes to `StepExecutor.recover`, read the windows from the run tables (`RunStore.attemptWindows`). An Attempt that ended before end times were recorded has no known window: it has no own window, and it is not listed as another Attempt's overlapping window.

`@usine/executor`: the durable session passes `Sink.windows` to the harvest, which reads the windows once GitHub has listed the comments, not when the Attempt is prepared or before the harvest starts. An Attempt that started later, even while the harvest ran, is therefore included, and so is the end the engine recorded when it canceled this Attempt. Startup reconciliation passes `RecoverySink.windows` to the harvest of a failed Attempt's comments. If the windows cannot be read, a finished Attempt's harvest fails, and an Attempt that ended without success records no comment.
