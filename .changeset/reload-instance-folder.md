The Loops, the Agents, and the `labels`, `repos`, `settings`, and `operator` keys of `usine.yaml` reload without a restart. `@usine/orchestrator/current-instance` exports `CurrentInstance`, whose `reload` loads the instance folder again with the startup loader and its per-file quarantine and returns an `InstanceReload` that names the Loops, Agents, labels, and repositories added, removed, or changed. Polling, schedules, queued-Event checks, GitHub App project discovery, Attempt settings, and the operator backend read the current instance when they act, so new Runs use the new configuration while an open Run keeps the Agent it was opened with. An invalid `usine.yaml` fails the reload with `FactoryConfigError`, and a changed `workers` or `webhooks` block fails it with `RestartRequiredError`; both keep the running configuration. The operator API adds `POST /api/instance/reload`. `Orchestrator.run`, `PollingTriggers.run(current)`, `ScheduleTriggers.run(current)`, `runtimeLayer(instanceDirectory)`, `triggerConditionLayer`, and `gitHubCredentialLayer` read the instance through `CurrentInstance` instead of taking a loaded instance, and the Worker layers need it for their Attempt settings.
