After a restart, a reattached Attempt holds a slot of the Worker it runs on, so that Worker takes no new Attempt beyond its `max_concurrent_attempts` while the reattached one runs. At startup, before any Run's fiber starts, the engine occupies a slot through `StepExecutor.occupy` for each open Attempt whose checkout it keeps for a reattachment, so a Run that arrives while the reattaching Run still reads whether the Attempt is live cannot take that slot. The Run reattaches the Attempt in that slot, or releases the slot when it does not reattach the Attempt, and canceling the Run before then releases it too. A Run that reattaches an Attempt without such a slot passes the Attempt's Worker to `StepExecutor.reserve`, and reads whether the Attempt is live again once it holds the slot, so an Attempt whose parent task stopped during the wait is reconciled instead of reattached. `RunStore.beginAttempt` logs `Reattached Attempt keeps its own Worker, not the reserved one` at error instead of warning.
