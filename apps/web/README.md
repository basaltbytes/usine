# @usine/web

The usine web UI, served by `@usine/server`. Internal — never published.

Needs you sits at the top of every screen: a two-column list of peach-tinted entries, each with its title, its Project, one line of detail, and its actions, such as Approve and Cancel Run for a Run waiting for approval, Reset cycle budget, or Discard leftovers. An approval names its Loop and the number and title of the Item its Run works on. The Worker not configured entry shows its whole detail, with its actions below it. An entry about a Run opens its drawer. The list is absent while nothing needs the operator, and the sidebar shows how many entries concern each Project. The first screen lists registered Projects, one row each: the repository, which opens its Board, its status (how many Needs you entries concern it, Active while it has open Runs, or Clear), its open Runs by running, queued, and waiting, and its Item and lane counts. With no Project registered, it points to `repos` in `usine.yaml` and offers **Reload configuration**. A project opens as a horizontal Board whose authored or proposed lanes group the latest GitHub issues and pull requests. Lanes that accept moves come first in their configured order, then the read-only lanes, with the unmatched lane last. The unmatched lane and lanes that hold only closed Items open folded into narrow rails showing their name and count; a rail opens into a lane, and the lane's heading folds it back. A lane is a heading with its name, card count, and the labels and Item states that route Items to it, labels in their GitHub colors, above a stack of Task cards; the heading stays in view while the cards scroll under it, an empty lane shows a dashed outline with No tasks, and during a drag the lane under the pointer gets a muted background. Between two adjacent authored label-backed lanes, an arrow at the end of the left lane's heading points to the next lane. While Tasks in the left lane have `Waiting`, `Queued`, or `Running` Runs, the arrow names those Runs' Loops, in blue when one of them is queued or running and in peach when they all wait for approval. A Task card joins explicitly linked issues and PRs. It shows each member's number and kind, PR for a pull request, the title on at most two lines, and up to three labels other than the lane's own with a count of the rest. When the task has an open Run, or a failed Run that still needs the operator, one line shows that Run's Loop, state, time, and Agent. The time counts from when the Run opened while it is `Waiting` or `Queued`, from when its current Attempt started while it is `Running`, and from the failure once it is `Failed`; its tooltip gives the full timestamp and what it counts from. The line starts with a dot in the state's color, which pulses while the Run is `Running`. Succeeded and canceled Runs stay in the drawer and Run history. Failures, with Retry when the failed Run can be retried, merge conflicts, Run action progress, and move progress appear below that line. Clicking a card opens its Run drawer, or the Item on GitHub when it has no Run. The card's menu lists only what applies: each member on GitHub, Open Run for the Run the card shows, Run history when the task has other Runs, Approve for a `Waiting` Run, Retry for a `Failed` one, Cancel Run after a confirmation for an open one, and Move to with the other writable lanes. Move to is absent when no other writable lane exists and while a move is saving. The menu button names the current issue or PR, whose labels a move changes. With a mouse it appears while the pointer is over the card, while the card has focus, and while its menu is open; on touch screens it is always shown. The drawer header links to the Item and to any pull request the Run produced. Authored label-backed lanes accept drag-and-drop moves; proposed, state-only, and unmatched lanes are read-only destinations. Cards can move only when another writable lane exists. Boards with proposed lanes explain how to enable moves by configuring `repos[].lanes` in `usine.yaml` and reloading the configuration.

A moved card stays in its destination while the label write and GitHub refresh finish. Progress distinguishes saving from a saved move awaiting synchronization; old lane labels are hidden during that wait. Other cards remain available, and navigating between Projects preserves accepted moves. An unrelated label update does not undo a move, while newer lane or Item state takes over normally. The Board checks for updates every second while moves are pending so confirmation and approval prompts appear promptly. Failed writes show their error and refresh authoritative state. The Board scrolls in both directions within the space below the Project heading; both ends remain reachable on desktop and narrow screens.

Opening a Run shows its conversation first, with Task, Event, and Attempts in separate tabs. Parent messages stay inline; each child session has a collapsible conversation and current activity status. Tool starts and finishes share one expandable row that identifies the command, file, search, or delegated task. Expanded tools use flat disclosure rows with indented details. Commands show terminal output, file reads show source, and edits show their patch or before-and-after text in distinct copyable panels. Other tools show labeled parameters and readable results; Raw details exposes the complete input and output. Everything, Messages, and Tools filters change the view without discarding history. Incoming activity follows the latest message until the reader scrolls away; Jump to latest resumes following. Load earlier preserves the reading position and remains available until every Attempt's full history is reachable. Account rate-window meters live in Attempts, separate from the conversation. Attempt failures include the typed reason, including executor defects that require an explicit retry, and an exhausted child-session budget shows both the configured and attempted counts in the drawer and Needs you. The separate Configuration view lists each Loop with its trigger, Agent, and state, and its database-backed **Pause** or **Resume** control. **Reload configuration** loads the instance folder again and lists what changed, or shows why the reload was refused. Needs-setup mode states that newly supplied GitHub App credentials require restarting `usine up` because the running process reads them only at startup.

The app uses React, TypeScript, TanStack Query, TanStack Router, Tailwind CSS, shadcn components on Base UI with Phosphor icons, and shadcn/typeset over react-markdown for prose. Its visual system follows ADR 0015: dark-only on Catppuccin Mocha. Mantle is the page, the sidebar, and the cards; the work panel is base, inset with a 1px hairline; menus, tooltips, and other floating surfaces are surface0. Secondary text is subtext0, and overlay0 marks graphics only because it is too faint for text. Mauve is the one action color: primary buttons, links, focus rings, selection, and the caret. Run states have semantic colors: blue running or queued, peach waiting and Needs you, red failed, green succeeded, and overlay canceled. Inter sets all text; JetBrains Mono sets ids, item numbers, times, and code.

Adjacent completed tools, including failed calls, have expandable action summaries, such as “Edited conversation.tsx · ran tests.” Groups show an error count when needed; error navigation opens the group and the failed call together. File summaries count distinct recorded paths and distinguish shared basenames with parent directories. Recognized test and build invocations describe what ran; their results remain in the tool details. Long or varied groups use compact counts, and loading earlier inputs fills in missing file and command details.

## Intervening in a Run

Send guidance from the parent conversation or a child's expanded activity. **Pause session** waits at the next tool boundary; sending a message resumes it. **Cancel Run** stops the entire Attempt.

Messaging a child places a Hold. The child can answer and accept more turns in the same conversation, while the parent continues waiting for its result. **Release child** lets the result return when the child is idle. Each child has its own Hold, and a paused parent does not prevent messaging its children. Held children remain reachable even when their last activity is outside the loaded transcript page. Holds pause the Attempt's elapsed-time budget; reported tokens continue counting toward `settings.max_attempt_tokens` when that ceiling is set. A failed or canceled Attempt shows the salvage branch its unfinished work was pushed to, or the retained worktree path when the push failed.

Failed Runs offer **Edit and retry** with a task editor and roster agent picker. The selected agent supplies its persona and model settings. The new task and agent apply to later Attempts, including automatic infrastructure retries. Attempts show the task and agent they actually used and whether they received an operator intervention. Messages and delivery receipts identify the configured operator in the transcript; the triggering Event remains unchanged.

## Returning to a conversation

Each Run remembers its filter, inspected groups, tools and child sessions, and reading place in this browser. Closing and reopening the drawer, or refreshing the page, returns to the same transcript row and position within it. A reader who leaves at latest continues following incoming activity. Wheel, touch, keyboard scrolling and conversation navigation take precedence over a pending restore.

The drawer loads up to 20 earlier pages automatically to recover a saved row. If the row is unavailable, a request fails, or recovery reaches that limit, a notice explains that the drawer is showing the nearest available activity. Load earlier remains available. Restoring a place, including this nearest-row recovery, preserves unread activity. The update count includes each loaded row changed since the last acknowledged tail once, including a tool result arriving after its start was read. Earlier pages can reveal additional unread rows. Jump to latest, or scrolling to latest in Everything, acknowledges those updates; error navigation and the Messages and Tools views preserve them.

Bookmarks expire after 30 days. This browser origin retains up to 20 Runs, the most recent 200 disclosure choices per Run, and at most 512,000 characters of bookmark data. Stored fields contain identities, preferences, a row-relative position and the acknowledged transcript sequence. Transcript text and tool payloads remain in the transcript store. If browser storage is disabled or full, the conversation remains usable; returning to a saved place requires available storage. See [ADR 0025](../../docs/adr/0025-run-conversation-reader-bookmarks.md).

## Conversation browser tests

Install the pinned Chromium browser once with `pnpm --filter @usine/web exec playwright install chromium`, then run `pnpm --filter @usine/web test`. The suite runs unit tests in Node and interaction tests in Chromium using the real MessageScroller, Base UI disclosures, sidebar, and browser layout. Board move tests use the actual HTTP client with controlled HTTP responses to replay stale refreshes, failures, concurrent card moves, and navigation during a request. CI installs Chromium and its operating-system dependencies before running the suite. A machine with its own Chromium, such as a Worker built by [`infra/hetzner/cloud-init.yaml`](../../infra/hetzner/cloud-init.yaml), sets `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to the browser's path instead; `vitest.config.ts` passes it to Playwright as `executablePath`, and `turbo.json` lists it in the `test` task's `env` so that `pnpm test` from the repository root sees it.

## How to add UI

The registry is the component library; the theme is the only place colors and type live.

- **Use a registry component first.** Everything under `src/components/ui/` came from `pnpm dlx shadcn@latest add <name>` (run inside `apps/web`; `components.json` holds the preset). Compose those primitives (`Item`, `Card`, `Badge`, `Sheet`, `Message`, `Collapsible`, `Empty`, …) in screen files. Before writing a new element, check whether a registry component already covers it; the full set is installed.
- **Extend with tokens, not hex.** Colors, fonts, and radii are CSS variables in `src/index.css`, exposed to Tailwind through the `@theme inline` block. A new semantic color is a new token pair there (`:root` and `.dark`) plus one `--color-*` line; screens then use utilities such as `text-run-active`. Never write a literal color in a component.
- **Never hand-roll a parallel component.** No `styles.css`, no ad-hoc button or badge classes. A composition shared by several screens (for example `src/components/status-badge.tsx`) wraps a registry primitive and lives in `src/components/`, next to `ui/`, so the distinction between vendored and composed stays visible.
- **Registry files are ours to edit.** Fix a type or a11y issue in place. They are exempt from the `usine/*` lint rules (see the `.oxlintrc.json` override) because upstream does not follow them, and `knip` treats them as entry files so unused components are not reported.
- **Conversation tools use AI Elements.** `src/components/ai-elements/` adapts the upstream Tool, CodeBlock, and Terminal components to Base UI, Phosphor icons, and the app's tokens; its README records provenance and adaptations. Compose these panels with readable tool content. Complete transport payloads belong under Raw details. shadcn MessageScroller owns conversation scrolling; every direct content row uses a stable `MessageScrollerItem` identity.
- **Markdown goes through `Markdown`.** `src/components/markdown.tsx` renders agent and operator prose with react-markdown inside a `typeset typeset-chat` container; `src/typeset.css` is the unmodified download from https://ui.shadcn.com/typeset.css and the `.typeset-chat` preset in `src/index.css` defines its settings. Source and patches use CodeBlock; command output uses Terminal.
- **A rebuilt bundle needs no restart.** `@usine/server` reads `index.html` and `assets/*` from `apps/server/dist/web` on every request, so after `pnpm build` a page reload serves the new bundle. GitHub credentials and the `workers` and `webhooks` blocks of `usine.yaml` are read at startup only; the rest of the instance folder reloads from the Loops page.
- **Screens are file routes.** `src/routes/` is the TanStack Router routes directory (`__root.tsx` shell, `index.tsx` projects, `projects/$owner/$name.tsx` board, `configuration/loops.tsx`); the Vite plugin regenerates `src/route-tree.gen.ts`, which is committed and excluded from lint and format. Route files export only `Route`; shared pieces live outside `src/routes/`. The run drawer is a root search param (`?run=`) so it overlays any screen.
- **Navigation lives in `src/components/app-sidebar.tsx`**, composed from the `sidebar` registry component; screens render inside `SidebarInset` under a breadcrumb header. The inset panel keeps the viewport's height, and the content below its header scrolls inside it.
- **Keep the scale.** `src/index.css` defines the only five sizes: `text-xs` 12px for captions and meta, `text-sm` 13px for body text and the default, `text-md` 14px for emphasised UI, `text-lg` 16px for section titles, and `text-xl` 20px for screen headings. Other size utilities generate no CSS, and arbitrary sizes are off the scale. Headings are Inter in semibold; `font-mono` is for ids, item numbers, times, and code only. Counts and times use `tabular-nums`. Sentence case everywhere; no uppercase labels.

An exhausted Item cycle budget appears in Needs you with the participating Loops and counts. **Reset cycle budget** records an explicit answer and refreshes the overview. The runtime fetches current trigger input before opening further work.

Expand a Claude or Codex child's activity to see its saved harness session id, worker worktree path, and copyable resume command. Run the command on the same worker under the same harness account. Resuming requires both the saved session files and the worktree; Attempt cleanup removes the worktree after completion. Older transcripts and Pi children show that no saved harness session was recorded.

A Loop or Agent file that failed to load at startup or at a reload appears in Needs you as **Loop quarantined** or **Agent file not loaded**, with the file and the reason. It stays there until the file is fixed and the configuration is reloaded.

A Worker that `usine.yaml` no longer declares appears in Needs you as **Worker not configured** while Attempts are recorded on it, with their count; startup doesn't reconcile those Attempts. Declare the Worker again and restart `usine up`, or choose **Discard leftovers**, then **Confirm discard**, to stop tracking them. Discarding removes nothing from the Worker.

Choose **Mark resolved** in a failed Run’s drawer to clear its Needs you warning and related Project and Board attention. Open the drawer from Needs you or Run history. Resolution persists across reloads and restarts; the failed outcome, Attempt details, transcript, and retry controls remain available. A later failed Attempt requests attention again.

An Agent's question appears in Needs you as **\<loop\> asks a question**, with the question. In its drawer the button reads **Mark answered**; the Run's Loop then acts on the Item's newest state.
