# @usine/docs

The usine documentation site uses [Astro Starlight](https://starlight.astro.build) and the [Lucode theme](https://lucas-labs.github.io/lucode-starlight-theme/). It is deployed to <https://docs.usine.dev> as the `usine-docs` Worker on the Basaltbytes Cloudflare account.

```sh
pnpm --filter @usine/docs dev         # local server with reload
pnpm --filter @usine/docs build       # test examples and build dist/
pnpm --filter @usine/docs preview     # serve dist/
pnpm --filter @usine/docs check       # check types and frontmatter
pnpm --filter @usine/docs test        # validate diagrams and the quickstart bootstrap
pnpm --filter @usine/docs run deploy  # upload dist/ to docs.usine.dev
```

Build workspace dependencies with `pnpm turbo run build --filter=@usine/docs^...` before using these commands from a fresh checkout. The docs package uses the workspace TypeScript version. The check command synchronizes content types and runs `tsc`; the site build compiles Astro and MDX templates and validates content schemas and links.

## Content and navigation

Pages are Markdown or MDX files in `src/content/docs/`. Get started contains the overview, quickstart, and concepts. Guides cover individual tasks. Reference contains the CLI, configuration formats, and operator HTTP API. `astro.config.mjs` defines the sidebar and top navigation; guide pages use `sidebar.order` to order autogenerated entries. Configuration entries link to the existing format references and their settings, projects, and workers sections.

Link to published pages by route, such as `/get-started/quickstart/`. The build validates links to pages and headings. `redirects.mjs` defines redirects for moved and removed routes, including the former guide landing page and package reference URLs. Add a redirect when moving a page.

Contributor architecture notes are outside the site in [`docs/architecture/`](../../docs/architecture/index.mdx). Each page states the commit it describes. The [workers and gateway page](../../docs/architecture/workers-and-gateway.mdx) describes harness logins, caller tokens, and cleanup of attempt Codex homes.

A fenced `mermaid` code block renders to SVG at build time with [Pele](https://pele.run/). The rehype plugin in `diagrams/rehype.mjs` runs for Markdown and MDX through Astro's unified processor. Invalid diagrams fail the build with the page path, fence position, and Pele error. Diagram colors use Starlight theme tokens through `--pele-*` variables in `src/styles/diagrams.css`, so switching themes updates the SVG through CSS.

Diagrams retain their measured label sizes. Wide diagrams scroll inside a keyboard-focusable frame, including on mobile. Prefer vertical layouts when a horizontal diagram would require extensive scrolling. `test/diagrams.test.ts` renders every diagram page in `src/content/docs/` through the same plugin during the docs build; it also checks parse failures and distinct SVG reference IDs for pages with multiple diagrams.

## Quickstart bootstrap

[`quickstart/`](quickstart/) contains the configuration files included by the quickstart page with raw imports. Keep instructions and examples in sync by editing these files rather than copying their content into the page.

[`test/quickstart.test.ts`](test/quickstart.test.ts) loads the folder through `ConfigurationFolder.load`. It checks that one project, agent, and loop load with the default local worker and verifies rejection of invalid configuration, agent, and loop files. The site build runs this test before rendering, and the root test gate also includes it.

## Operator HTTP API reference

The [operator API reference](src/content/docs/reference/operator-api.mdx) renders `public/openapi.json`, a committed OpenAPI 3.1 document generated from the operator and authentication route contracts. Each docs build regenerates it before rendering. Download it from `/openapi.json` on the docs site, or use `/api/openapi.json` on a running instance.

The `@usine/orchestrator` development dependency ensures that Turborepo builds the contracts imported through the server's OpenAPI generator. Knip excludes this dependency from unused-dependency reports because the import is in the server package.

After changing an API contract, build its dependencies and regenerate the document:

```sh
pnpm turbo run build --filter=@usine/docs^...
pnpm --filter @usine/docs openapi:generate
pnpm --filter @usine/docs openapi:check
```

Commit the updated JSON with the contract change. `openapi:check` compares the file without modifying it. The root `pnpm check` also checks the Git diff after the docs build, so CI regeneration cannot hide a stale committed document. Turborepo includes server contract sources in the docs build inputs and caches the generated JSON with the site.

## Deployment

`wrangler.jsonc` configures the Worker to serve `dist/` as static assets on `docs.usine.dev`. The `Deploy docs` workflow (`.github/workflows/deploy-docs.yml`) builds and deploys on relevant pushes to `main`, using the `CLOUDFLARE_API_TOKEN` repository secret.

To deploy by hand, run `pnpm turbo run build --filter=@usine/docs` first, then authenticate with `npx wrangler login` and run the deploy command. Deployment uploads `dist/` as it is.
