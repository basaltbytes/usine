## One Attempt end to end

```mermaid
sequenceDiagram
  participant F as Run fiber
  participant S as StepExecutor
  participant X as Executor
  participant P as Pi parent
  participant C as Child
  F->>F: beginAttempt
  F->>S: execute
  S->>X: prepare
  Note over X: credentials,<br/>worktree
  S->>X: launch
  X->>P: execute
  P->>C: subagent
  C-->>P: session events
  P-->>F: envelopes
  C-->>P: result
  P-->>X: report
  Note over X: harvest,<br/>recordResult
  Note over X: release the<br/>checkout
  X-->>F: StepResult
  F->>F: finishAttempt
```

The fiber begins the Attempt and hands `StepExecutor` a sink for envelopes. `StepExecutor` has the executor prepare the checkout with fresh credentials, then launch the Attempt, which runs the Pi parent task through `AttemptRuntime.execute`. The parent starts children with its `subagent` tool. Every envelope of the parent and its children passes the runaway guard and reaches the fiber's sink, which appends it to the transcript. When the parent reports, the executor harvests the checkout, stores the result with the task, and releases the checkout before `launch` returns, so the worktree is removed or its salvage is recorded before the fiber calls `finishAttempt`.

## The executor contract

`Executor` ([executor.ts:172](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/executor.ts#L172)) is the seam of [ADR 0006](https://github.com/basaltbytes/usine/blob/main/docs/adr/0006-executor-contract-run-host-attempt-channel.md):

| Operation                            | Does                                                                                                                                                                              |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`                               | The Worker kind the executor runs. `StepExecutor` refuses a configured Worker of another kind.                                                                                    |
| `preflight(worker, brains)`          | Verifies Git and each rostered brain where the Worker runs children. Installs nothing.                                                                                            |
| `prepare(request)`                   | Needs a `Scope`. Checks the Attempt's brain again, gets repository access, creates or reattaches the checkout, and returns a `PreparedAttempt` with `workspace` and `launch(io)`. |
| `cancel(attemptId)`                  | Stops preparation, or cancels the live parent task, waits a grace period, then interrupts.                                                                                        |
| `intervene(attemptId, intervention)` | Delivers an operator action to the live session.                                                                                                                                  |
| `isLive`, `outcome`                  | Tell a restarted engine whether to reattach an open Attempt or finish it with a stored result.                                                                                    |
| `recover(attempt, record)`           | Salvages or removes a checkout an earlier process left.                                                                                                                           |

```ts title="packages/executor/src/executor.ts"
/** Prepares isolated checkouts, runs Attempts on a Worker, and releases their resources (ADR 0006). */
export class Executor extends Context.Service<
  Executor,
  {
    /** Reconciles an old checkout before new Attempts start; records its salvage before releasing any work. */
    readonly recover: <E>(
      attempt: AttemptRecovery,
      record: (salvage: AttemptSalvage) => Effect.Effect<void, E>,
    ) => Effect.Effect<void, E | ExecutorError>;
    readonly kind: WorkerKind;
    /**
     * Whether the Attempt's parent task survived an orchestrator restart and can be reattached:
     * it still runs, or it reported success before its checkout was harvested.
     */
    readonly isLive: (attemptId: AttemptId) => Effect.Effect<boolean, AttemptFailure>;
    /**
     * The result an Attempt's finished parent task left in durable storage before an
     * orchestrator restart: the harvested result, or the parent's failure. None when
     * nothing was stored, or when `isLive` says the Attempt is reattached instead.
     */
    readonly outcome: (
      attemptId: AttemptId,
    ) => Effect.Effect<Option.Option<Result.Result<StepResult, AttemptFailure>>, AttemptFailure>;
    /** Verifies Git and each rostered brain where the Worker runs children; never installs tools or logs in. */
    readonly preflight: (
      worker: WorkerName,
      brains: ReadonlyArray<BrainSpec>,
    ) => Effect.Effect<void, ExecutorError>;
    /**
     * Verifies the assigned brain before acquiring the Attempt in the caller's scope. Clone, fetch, and lock waits
     * remain interruptible; partial preparation releases everything already acquired
     * before reporting failure. Each request identifies a fresh Attempt, or a live one
     * to reattach when `reattach` is set.
     */
    readonly prepare: (
      request: CheckoutRequest,
    ) => Effect.Effect<PreparedAttempt, ExecutorError, Scope.Scope>;
    /**
     * Stops preparation and releases partial resources, or cancels the live
     * parent task with a grace period before forced termination. A canceled prepared Attempt
     * cannot launch. Repeated cancellation after release is a no-op.
     */
    readonly cancel: (attemptId: AttemptId) => Effect.Effect<void, ExecutorError>;
    /** Delivers an attributed operator action to the active Attempt's live session. */
    readonly intervene: (
      attemptId: AttemptId,
      intervention: AttemptChannel.Intervention,
    ) => Effect.Effect<void, AttemptFailure>;
```

### Preparing the checkout

`provisionWorktree` ([provision.ts:233](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/provision.ts#L233)) is the same for every Worker kind. Under a per-repository lock it clones into a staging directory (`git clone --bare --filter=blob:none`) and renames it to the cache, or updates the cache's remote URL. Then it fetches the revision, records `FETCH_HEAD` as the base commit, fetches the previous Attempt's salvage when the request resumes one, and runs `git worktree add --detach`. The worktree is `<worker directory>/attempts/<attempt id>` and the cache is `<worker directory>/repos/<repository>.git`, where both names replace every character other than letters, digits, `_`, `.`, and `-` with `_` ([provision.ts:21](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/provision.ts#L21)).

### Launch, guard, release

`launch` ([prepared-attempt.ts](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/prepared-attempt.ts)) wraps the sink with the runaway guard ([prepared-attempt.ts:114](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/prepared-attempt.ts#L114)) and races the parent task against the guard's wall-clock trip. The guard ([guard.ts:139](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/guard.ts#L139)) arms only the ceilings `usine.yaml` sets. The token meter sums the highest `SessionTokensUpdated` count per session ([guard.ts:32](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/guard.ts#L32)). The wall clock pauses while any child is held ([guard.ts:64](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/guard.ts#L64)). At 80% of either ceiling ([guard.ts:8](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/guard.ts#L8)) the guard sends the parent one `Steer` from operator `engine` ([prepared-attempt.ts:119](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/prepared-attempt.ts#L119)). A trip stops the Attempt and fails it with `RunawayFailure`.

When the parent reports success, the executor harvests the checkout with `harvestFacts` ([harvest.ts:135](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/core/src/step/harvest.ts#L135)): the commits from the base commit to `HEAD`, then the pull requests whose head is the final commit, from `gh api repos/<repo>/commits/<head>/pulls`. Pull request discovery has a ten-second timeout and never fails the Attempt. `StepResult` also allows a `Comment` fact ([result.ts:20](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/core/src/step/result.ts#L20)), but no code produces one.

Any end other than success runs `salvageWorktree` ([salvage.ts:56](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/salvage.ts#L56)) before the worktree is removed. Uncommitted changes become a `wip(usine): salvage attempt <id>` commit, and `git push --force` sends HEAD to `usine/salvage/<run>/<number>`. A failed push keeps the worktree on the Worker and records its path as `Retained`. The next Attempt of the Run checks out the newest pushed salvage ([ADR 0013](https://github.com/basaltbytes/usine/blob/main/docs/adr/0013-cost-accounting-native-meters-guardrails.md), amendment of 2026-09-18).

## The durable layer

`AttemptRuntime` ([attempt-runtime.ts:70](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt-runtime.ts#L70)) runs the Pi parent as a pi-durable task called `usine.attempt` ([task.ts:46](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt/task.ts#L46)). Its storage is `.usine/durable.sqlite` ([storage-path.ts:5](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/storage-path.ts#L5)), opened by `@earendil-works/pi-durable` 1.1.0. Building the layer ([live.ts:74](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/live.ts#L74)) resumes every unfinished task ([runtime.ts:50](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt/runtime.ts#L50)).

| Operation              | Does                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `execute(request, io)` | Creates the task, or finds it after a restart, relays its activity to `io`, and waits for the parent's report.        |
| `isLive`, `finished`   | Whether the task is still open, and what a finished task left: `ParentReported`, `ResultRecorded`, or `ParentFailed`. |
| `recordResult`         | Stores the harvested `StepResult` with the task.                                                                      |
| `request`              | The stored request of a task, read for a reattachment.                                                                |
| `intervene`            | Applies an operator action to the parent or a child.                                                                  |
| `cancel`               | Aborts children, then the parent conversation.                                                                        |

The stored request contains the RunSpec, the Worker, and the worktree path ([attempt-runtime.ts:14](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt-runtime.ts#L14)). The child host and the environment are not stored. Every `execute` call supplies them again, because the environment contains the Attempt's credential configuration ([ADR 0011](https://github.com/basaltbytes/usine/blob/main/docs/adr/0011-github-app-identity-scoped-worker-tokens.md)).

The parent's first turn is the prompt from `assemblePrompt` ([prompt.ts:58](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/agents/src/prompt.ts#L58)): the repository, the salvage it resumes from, the Event payload as JSON, the Agent persona, the task text, completion rules, and GitHub rules (review with `COMMENT` only, and end every comment, issue, pull request, and review with the signature line from `githubSignature`, which ends in `usine agent: <name>`, [prompt.ts:28](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/agents/src/prompt.ts#L28)). The parent's only tool is `subagent` ([subagent.ts:31](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt/subagent.ts#L31)). Each call starts one child of the Agent's harness in the checkout. The tool is declared `replay: "unsafe"` ([subagent.ts:271](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt/subagent.ts#L271)): after a restart the interrupted call settles with the output committed so far, and the parent decides whether to delegate again. A final answer that starts with `[usine:blocked]` fails the Attempt with `AgentFailure` ([task.ts:58](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/durable/src/attempt/task.ts#L58)). The `children` count in the Attempt record enforces `max_children`; one more spawn fails the Attempt with `ChildSessionBudgetFailure`.

The parent's billing pool follows its provider: a model from `openai-codex` uses the ChatGPT plan and every other model uses API keys ([authentication.ts:30](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/agents/src/pi/authentication.ts#L30), [ADR 0021](https://github.com/basaltbytes/usine/blob/main/docs/adr/0021-pi-parent-pool-follows-authentication.md)).

### Reattach after a restart

<Steps>

1. `RunDriver.openAttempt` ([run-driver.ts:234](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/engine/src/engine/run-driver.ts#L234)) asks `isLive`. The durable session answers true when the task is live, or when it finished with `ParentReported` and nothing harvested it yet ([durable-session.ts:396](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/durable-session.ts#L396)).

2. `beginAttempt` returns `ReattachAttempt`: same Attempt id and number, no retry spent ([lifecycle.ts:132](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/engine/src/engine/lifecycle.ts#L132)).

3. `prepare` with `reattach` reads the stored RunSpec, issues fresh credentials, and takes over the existing worktree.

4. `execute` finds the task in storage and continues its relay from the stored sequence.

</Steps>

An Attempt whose task is gone fails as an `InfraFailure`, and the next Attempt starts from the newest pushed salvage. Interrupting a launch that nobody stopped means this process is stopping, so the task stays live and the worktree stays on disk ([durable-session.ts:193](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/executor/src/durable-session.ts#L193)).

## The Attempt channel and the transcript

The envelopes are defined in [channel.ts](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/core/src/attempt/channel.ts), protocol version 7. Outbound payloads are `Started`, `SessionEvent`, `Final`, `Failed`, `Interrupted`, `InterventionApplied`, and `InterventionRejected`. Inbound payloads are `Steer`, `Interrupt`, `OperatorMessage`, `Release`, and `Cancel`, each with a target: the parent or a child session id. `admit` ([channel.ts:221](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/core/src/attempt/channel.ts#L221)) enforces the order: one `Started` or `Failed` first, contiguous sequences, nothing after the terminal envelope.

The next sequence numbers are in the durable Attempt record, so a relay that restarts continues the same sequence.

The sink that the Run fiber hands to the executor calls `RunStore.appendTranscript` ([store.ts:546](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/engine/src/store/store.ts#L546)). ## The live channel for interventions

Operator input never becomes an Event ([ADR 0018](https://github.com/basaltbytes/usine/blob/main/docs/adr/0018-takeover-and-edit-and-retry.md)). It takes this path:

```mermaid
sequenceDiagram
  participant O as Operator
  participant E as RunEngine
  participant D as Durable session
  participant R as AttemptRuntime
  Note over O: POST intervene,<br/>attributed
  O->>E: intervene
  Note over E: Running, latest<br/>open Attempt?
  E->>D: intervene
  Note over D: live session<br/>in this process?
  D->>R: intervene
  Note over R: record inbound,<br/>apply to target
  R-->>E: Applied or<br/>Rejected
```

<Steps>

1. `POST /api/runs/:runId/intervene` with the Attempt id, the target, and the action.

2. `Operator.intervene` ([operator.ts:471](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/orchestrator/src/operator/operator.ts#L471)) attributes it to `operator` from `usine.yaml`, or to `local operator`.

3. `RunEngine.intervene` ([engine.ts:120](https://github.com/basaltbytes/usine/blob/7c0c3d3696123d11e3d5b9cc3d27e18bb21e84e9/packages/engine/src/engine/engine.ts#L120)) refuses unless the Run is `Running` and the Attempt is its latest open one.
