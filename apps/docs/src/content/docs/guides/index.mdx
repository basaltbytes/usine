A factory is one orchestrator process that you start with `usine up` from an instance folder. The folder contains the database in `.usine/`, including configuration, its revision history, and runtime state. Keep `.usine/` and secrets out of git.

## Before you begin

You need:

- Node.js 22 or later, npm, and Git on the orchestrator machine.
- A GitHub account or organization that owns the repositories, where you can create and install a GitHub App.
- The harnesses that your agents use, logged in on the machine that runs the child sessions: Claude Code with a Claude subscription, or Codex CLI 0.164.0 (or 0.159.0 through 0.159.3 for one release) with a ChatGPT login. With the default local worker, this is the orchestrator machine and the user who runs `usine up`.
- A model credential in Pi's configuration for the Pi parent of each attempt. See [Pi parent](/guides/write-an-agent/#pi-parent).

## Install usine

Install the CLI and web UI from npm:

```sh title="Orchestrator machine"
npm install --global @usine/server
```

The package provides the `usine` command. To update it, run `npm install --global @usine/server@latest`, then run `usine restart` from the instance folder when no attempt is running. For a systemd installation, see [Server upgrades](/guides/run-the-orchestrator-on-a-server/#upgrade-the-server).

## Create the instance folder

Create an empty folder and start usine there:

```sh
mkdir -p ~/my-factory
cd ~/my-factory
usine up
```

The first start saves an empty configuration revision in the database. Use the web UI to add repositories, projects, agents, and loops. Existing instance folders with `usine.yaml` import their configuration on the first start; later starts read the database. [`usine config import` and `export`](/reference/configuration/config/) support file-based configuration transfers.

<FileTree>

- my-factory/
  - .env optional environment overrides
  - .usine/ runtime state and secrets
    - runtime.sqlite configuration, revisions, and runs
    - durable.sqlite sessions
    - github-app.json App credentials, mode 0600
    - admin-token local API credential, mode 0600

</FileTree>

Keep `.usine/` and `.env` out of git and include them in your instance backups.

## Connect a GitHub App

usine uses one GitHub App. The orchestrator polls and writes labels with an installation token. Each attempt gets its own token, limited to its repository, that expires within one hour. The App's private key stays on the orchestrator machine.

<Steps>

1. Open the sign-in link printed by `usine up`. For a detached server, run `usine sign-in-link` in the instance folder and open that link. It opens a temporary setup session.

2. Enter an App name on the setup page. To create the App for an organization, enter its GitHub login. Select **Create App on GitHub** and confirm on GitHub. usine supplies the required permissions, event subscriptions, sign-in callback, and webhook URL. For a remote instance, set `USINE_ORIGIN` to its public HTTPS address before starting setup.

3. GitHub returns to usine, which saves the App ID, private key, client ID, client secret, and webhook secret together in `.usine/github-app.json` with mode `0600`. Setup reads the saved credentials and preserves your setup session.

4. Select **Install App on GitHub**, choose the account and repositories, and return to setup. Select **Check installation**. usine requires exactly one active installation with the requested permissions.

5. Select **Sign in with GitHub**. The member who completes this sign-in becomes the first instance admin, and the temporary setup session ends. Select **Add repositories** to activate the runtime and open the installation repository picker. Create a project for those repositories, then add your agents and loops.

</Steps>

Open `/setup` to resume an interrupted setup. It detects missing credentials, an App awaiting installation, or an installation whose registry is empty. If App creation finished on GitHub but its credentials were lost, open **I already have an App** to restore credential JSON. Generate a replacement private key in the App settings if necessary. Existing manual credential files and environment overrides remain supported.

## Start the orchestrator

From the instance folder, run `usine up`. An empty folder starts with an empty configuration revision. An existing bootstrap configuration imports as revision 1, preserving loop pause state. Later starts read the database and ignore the original configuration files:

```sh title="Instance folder"
usine up
```

The process runs in the foreground and prints `usine is running at http://127.0.0.1:7331`. If a startup check fails, `usine up` stops with a message that says what to fix. If the GitHub App credentials are missing or invalid, it starts in setup mode and opens the setup page in your browser. [Startup](/reference/configuration/cli/#startup) lists the checks, flags, and setup mode.

To run the orchestrator in the background instead, run `usine up --detach`. It returns once the orchestrator listens, and the orchestrator writes its output to `.usine/usine.log`. Then manage it from the instance folder:

```sh title="Instance folder"
usine status    # whether it runs, its PID, address, version, uptime, and open runs
usine restart   # stop after the drain, and start again in the background
usine stop      # stop after the drain
```

See [Operate runs](/guides/operate-runs/#stop-the-orchestrator) for the drain and for upgrades.

### Keep the machine awake

The orchestrator must keep running while runs are open. A sleep closes its SSH connections to workers and to the gateway: after the machine wakes, a remote Claude Code child resumes its session, and a Codex child fails. On macOS, `usine up` warns at startup if the Mac can sleep. For a factory that runs unattended, [run the orchestrator on a server](/guides/run-the-orchestrator-on-a-server/) instead of a laptop. To keep a Mac awake:

- Run `caffeinate -s` in another terminal while runs are open. It keeps a Mac on AC power awake until you stop it. To stop it with the orchestrator, run `caffeinate -s -w "$(cat .usine/instance.pid)"` from the instance folder.
- Turn off system sleep on AC power with `sudo pmset -c sleep 0`.

Closing a laptop's lid also puts it to sleep, unless it runs in closed-display mode with power and an external display.

## Open the web UI

The UI is at `http://127.0.0.1:7331`, or on the port you set. The server listens only on the loopback interface and has no login. It refuses browser requests from pages on non-loopback origins, other than the URL of a proxy that [`--origin`](/reference/configuration/cli/#usine-up) sets, so other websites can't use it through your browser. To use the UI from another computer, forward the port over SSH, or publish it on your tailnet as in [Run the orchestrator on a server](/guides/run-the-orchestrator-on-a-server/#keep-the-ui-private):

```sh title="Your computer"
ssh -N -L 7331:127.0.0.1:7331 orchestrator.example.com
```

The sidebar lists projects by display name, with **Board** and **Tasks** for each project. A project combines one or more repositories in one board. **Configuration > Projects** edits display names, ordered repositories, and shared lanes; **Repositories** manages registry entries. Configuration edits save revisions and apply live. [Operate runs](/guides/operate-runs/) describes each screen.

## Runtime state

usine writes its state to `.usine/` in the instance folder:

| Path                                          | Contents                                                                                                                                                                                                                                                                         |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.usine/runtime.sqlite`                       | Events, runs, attempts, transcripts, board projections, poll cursors, and loop pause flags. usine never deletes a row.                                                                                                                                                           |
| `.usine/durable.sqlite`                       | The Pi parent task and conversation of each attempt, which usine resumes after a restart.                                                                                                                                                                                        |
| `.usine/github-app.json`                      | The App credentials, if you use the file.                                                                                                                                                                                                                                        |
| `.usine/instance.lock`, `.usine/instance.pid` | The lock that prevents a second `usine up`, and the process ID of the running one.                                                                                                                                                                                               |
| `.usine/instance.json`                        | The [instance record](/reference/configuration/cli/#instance-record) of the running `usine up`.                                                                                                                                                                                  |
| `.usine/instance-id`                          | The instance's ID, which labels its attempt containers on SSH workers.                                                                                                                                                                                                           |
| `.usine/usine.log`                            | The output of an orchestrator that `usine up --detach`, `usine restart`, or `usine upgrade` started.                                                                                                                                                                             |
| `.usine/backups/`                             | The copies of the stores that `usine upgrade` makes before it moves the pin.                                                                                                                                                                                                     |
| `.usine/workers/<worker>/`                    | For a local worker: cached clones in `repos/`, attempt worktrees in `attempts/`, and the Turborepo cache in `turbo/`.                                                                                                                                                            |
| `.usine/known-hosts/`                         | The host key of each machine that a [provisioned worker](/guides/add-a-provisioned-worker/) created, one file per machine.                                                                                                                                                       |
| `.usine/ssh-workers/`                         | How to reach each SSH worker that has a `destination`, one file per worker, without secrets. **Discard leftovers** reads it to remove the attempts' Codex homes from a worker that the stored configuration no longer declares (see [Restarts](/guides/operate-runs/#restarts)). |

The runtime store records every event, so that a loop doesn't act twice on the same item content. Deleting it deletes configuration, revision history, this record, and the run history, so back it up with [`usine backup`](/guides/operate-runs/#back-up-and-export) instead.

## Change the configuration

For command-line changes, run `EDITOR=vi usine config edit settings instance`, `usine config edit worker local`, or `usine config edit loop widgets/start-dev`. To add entities or change several together, export a folder, edit it, and import it with a message. See [`usine config`](/reference/configuration/config/) for every entity kind and the fields that require a restart.

Open **Configuration** to change loops, agents, workers, repositories, labels, or settings. On a detail page, select **Edit**, change the export-format text, optionally enter a message, and select **Save**. Errors appear below the editor with their field paths. If another change was saved first, review the newer revision's diff and select **Reload text**; your draft remains below the editor for copying.

Use **New** on a list to create an entity from a template. New loops start paused; review the trigger and prompt before selecting **Resume**. **Delete** shows the entity name and affected loops or projects before confirmation. Removing a label declaration does not delete labels on GitHub.

Each detail page has **History**, with revision numbers, actors, times, and messages. Select a revision to see the before-and-after text as a diff. **Revert** creates a revision restoring every entity in the selected revision, with an optional message. A later change to an affected entity can prevent a revert. **Configuration > History** lists all revisions and links to the changed entities.

Revisions accepted by the UI apply live to new work; running attempts continue. The UI refuses a change that needs a restart or fails worker preflight. CLI writes save these revisions, but the running configuration stays unchanged until the restart or preflight succeeds. For command-line editing and bulk changes, use [`usine config edit`, `import`, `export`, and `log`](/reference/configuration/config/). Files are an import and export format; editing the original files does not change the stored configuration.
