A factory is one orchestrator process that you start with `usine up` from an instance folder. The folder contains bootstrap files and the database in `.usine/`, including configuration, its revision history, and runtime state. Keep `.usine/` and secrets out of git.

## Before you begin

You need:

- Node.js 22 or later, pnpm 11, and Git on the orchestrator machine.
- A GitHub account or organization that owns the repositories, where you can create and install a GitHub App.
- The harnesses that your agents use, logged in on the machine that runs the child sessions: Claude Code with a Claude subscription, or Codex CLI 0.153.4 or 0.159.0 through 0.159.3 with a ChatGPT login. With the default local worker, this is the orchestrator machine and the user who runs `usine up`.
- A model credential in Pi's configuration for the Pi parent of each attempt. See [Pi parent](/guides/write-an-agent/#pi-parent).

## Install usine

Clone and build the usine repository:

```sh title="Orchestrator machine"
git clone https://github.com/basaltbytes/usine.git
cd usine
pnpm install --frozen-lockfile
pnpm build
```

The build writes the CLI to `apps/server/dist/main.js` and the web UI to `apps/server/dist/web`. On this site, `usine` means `node /path/to/usine/apps/server/dist/main.js`. To use the same command, add an alias:

```sh title="~/.zshrc"
alias usine="node /path/to/usine/apps/server/dist/main.js"
```

The `@usine/server` package is on npm, but installing it with npm fails at this commit because of a dependency range ([#233](https://github.com/basaltbytes/usine/issues/233)).

To update usine, pull, run `pnpm install --frozen-lockfile` and `pnpm build` again, and run `usine restart` from the instance folder. The server reads the UI files on every request, so after a UI-only rebuild, reload the page.

## Create the instance folder

The first start imports the files below into the database as revision 1. Later starts read only the stored configuration. Use [`usine config edit`, `import`, `export`, and `log`](/reference/configuration/cli/#configuration-revisions) to change configuration and inspect its history. `.env`, the GitHub App credentials, and the listen address remain in files or environment variables.

<FileTree>

- my-factory/
  - usine.yaml registry, labels, settings, and workers
  - agents/
    - developer.md one agent per file
  - loops/
    - start-dev.md one loop per file
  - .gitignore
  - .env secrets that usine reads, such as tokens
  - .usine/ runtime state that usine up writes
    - runtime.sqlite
    - durable.sqlite
    - github-app.json
    - instance.lock
    - instance.pid
    - instance.json
    - instance-id
    - usine.log
    - backups/
    - workers/

</FileTree>

<Steps>

1. Create the folder with a `usine.yaml` file and the `agents/` and `loops/` folders. `usine up` stops if either folder is missing, even if it would be empty.

2. Register the repositories in `usine.yaml`. This is the smallest valid file:

   ```yaml title="usine.yaml"
   version: 1
   repos:
     - name: acme/widgets
   ```

   A fuller file declares labels, board lanes, settings, workers, and your GitHub login:

   ```yaml title="usine.yaml"
   version: 1
   labels:
     - name: ready-for-agent
       color: "0e8a16"
       description: The developer Agent may start this issue
     - name: ready-for-review
   repos:
     - name: acme/widgets
       tags: [backend]
       lanes:
         - name: Ready
           sources: [{ label: ready-for-agent }]
         - name: Review
           sources: [{ label: ready-for-review }]
         - name: Done
           sources: [{ state: pr-merged }, { state: issue-closed }]
   settings:
     poll_interval: 60
   workers:
     - name: local
       kind: local
       max_concurrent_attempts: 2
   operator: your-github-login
   ```

   [`usine.yaml`](/reference/configuration/usine-yaml/) lists every key and its default.

3. Add at least one [agent](/guides/write-an-agent/) and one [loop](/guides/write-a-loop/).

4. Keep the runtime state and the [environment file](/reference/configuration/cli/#environment-file) out of git:

   ```text title=".gitignore"
   .usine/
   .env
   ```

</Steps>

## Connect a GitHub App

usine uses one GitHub App. The orchestrator polls and writes labels with an installation token. Each attempt gets its own token, limited to its repository, that expires within one hour. The App's private key stays on the orchestrator machine.

<Steps>

1. In the settings of the account or organization that owns the repositories, open **Developer settings** > **GitHub Apps** > **New GitHub App**. Set **Where can this GitHub App be installed?** to **Only on this account**.

2. Under **Webhook**, clear **Active**. usine polls GitHub and doesn't use webhooks.

3. Set these repository permissions, and leave all other permissions at **No access**:

   | Permission    | Access         |
   | ------------- | -------------- |
   | Checks        | Read-only      |
   | Contents      | Read and write |
   | Issues        | Read and write |
   | Metadata      | Read-only      |
   | Pull requests | Read and write |

   usine requests exactly these permissions for every token and refuses an installation that lacks one. With **Workflows** at **No access**, attempt tokens can't change `.github/workflows/`.

4. Create the App, generate a private key, and note the App ID.

5. On the App's **Install App** page, install the App on the account that owns the repositories, and select every repository in `usine.yaml`. usine expects exactly one installation and refuses a suspended one.

6. Save the credentials in `.usine/github-app.json` with mode `0600`:

   ```sh title="Instance folder"
   mkdir -p .usine
   install -m 600 /dev/null .usine/github-app.json
   jq -n --argjson app_id "$APP_ID" --rawfile private_key factory.private-key.pem \
     '{app_id: $app_id, private_key: $private_key}' > .usine/github-app.json
   ```

   You can set `USINE_GITHUB_APP_ID` and `USINE_GITHUB_PRIVATE_KEY` instead. See [Environment variables](/reference/configuration/cli/#environment-variables).

</Steps>

## Start the orchestrator

From the instance folder, run `usine up`:

```sh title="Instance folder"
usine up
```

The process runs in the foreground and prints `usine is running at http://127.0.0.1:7331`. If a startup check fails, `usine up` stops with a message that says what to fix. If the GitHub App credentials are missing or invalid, it starts in setup mode and opens the setup page in your browser. [Startup](/reference/configuration/cli/#startup) lists the checks, flags, and setup mode.

To run the orchestrator in the background instead, run `usine up --detach`. It returns once the orchestrator listens, and the orchestrator writes its output to `.usine/usine.log`. Then manage it from the instance folder:

```sh title="Instance folder"
usine status    # whether it runs, its PID, address, version, uptime, and open runs
usine restart   # stop after the drain, and start again in the background
usine stop      # stop after the drain
```

See [Operate runs](/guides/operate-runs/#stop-the-orchestrator) for the drain and for upgrades.

### Keep the machine awake

The orchestrator must keep running while runs are open. A sleep closes its SSH connections to workers and to the gateway: after the machine wakes, a remote Claude Code child resumes its session, and a Codex child fails. On macOS, `usine up` warns at startup if the Mac can sleep. For a factory that runs unattended, [run the orchestrator on a server](/guides/run-the-orchestrator-on-a-server/) instead of a laptop. To keep a Mac awake:

- Run `caffeinate -s` in another terminal while runs are open. It keeps a Mac on AC power awake until you stop it. To stop it with the orchestrator, run `caffeinate -s -w "$(cat .usine/instance.pid)"` from the instance folder.
- Turn off system sleep on AC power with `sudo pmset -c sleep 0`.

Closing a laptop's lid also puts it to sleep, unless it runs in closed-display mode with power and an external display.

## Open the web UI

The UI is at `http://127.0.0.1:7331`, or on the port you set. The server listens only on the loopback interface and has no login. It refuses browser requests from pages on non-loopback origins, other than the URL of a proxy that [`--origin`](/reference/configuration/cli/#usine-up) sets, so other websites can't use it through your browser. To use the UI from another computer, forward the port over SSH, or publish it on your tailnet as in [Run the orchestrator on a server](/guides/run-the-orchestrator-on-a-server/#keep-the-ui-private):

```sh title="Your computer"
ssh -N -L 7331:127.0.0.1:7331 orchestrator.example.com
```

The sidebar lists **Projects**, with one board per repository, and **Configuration**, whose **Loops**, **Agents**, **Workers**, **Repositories**, and **Settings** pages show your files as usine parsed them. [Operate runs](/guides/operate-runs/) describes each screen.

## Runtime state

usine writes its state to `.usine/` in the instance folder:

| Path                                          | Contents                                                                                                                                                                                                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.usine/runtime.sqlite`                       | Events, runs, attempts, transcripts, board projections, poll cursors, and loop pause flags. usine never deletes a row.                                                                                                                                               |
| `.usine/durable.sqlite`                       | The Pi parent task and conversation of each attempt, which usine resumes after a restart.                                                                                                                                                                            |
| `.usine/github-app.json`                      | The App credentials, if you use the file.                                                                                                                                                                                                                            |
| `.usine/instance.lock`, `.usine/instance.pid` | The lock that prevents a second `usine up`, and the process ID of the running one.                                                                                                                                                                                   |
| `.usine/instance.json`                        | The [instance record](/reference/configuration/cli/#instance-record) of the running `usine up`.                                                                                                                                                                      |
| `.usine/instance-id`                          | The instance's ID, which labels its attempt containers on SSH workers.                                                                                                                                                                                               |
| `.usine/usine.log`                            | The output of an orchestrator that `usine up --detach`, `usine restart`, or `usine upgrade` started.                                                                                                                                                                 |
| `.usine/backups/`                             | The copies of the stores that `usine upgrade` makes before it moves the pin.                                                                                                                                                                                         |
| `.usine/workers/<worker>/`                    | For a local worker: cached clones in `repos/`, attempt worktrees in `attempts/`, and the Turborepo cache in `turbo/`.                                                                                                                                                |
| `.usine/known-hosts/`                         | The host key of each machine that a [provisioned worker](/guides/add-a-provisioned-worker/) created, one file per machine.                                                                                                                                           |
| `.usine/ssh-workers/`                         | How to reach each SSH worker that has a `destination`, one file per worker, without secrets. **Discard leftovers** reads it to remove the attempts' Codex homes from a worker that `usine.yaml` no longer declares (see [Restarts](/guides/operate-runs/#restarts)). |

The runtime store records every event, so that a loop doesn't act twice on the same item content. Deleting it deletes this record and the run history, so back it up with [`usine backup`](/guides/operate-runs/#back-up-and-export) instead.

## Change the configuration

Open **Configuration** to change loops, agents, workers, repositories, labels, or settings. On a detail page, select **Edit**, change the export-format text, optionally enter a message, and select **Save**. Errors appear below the editor with their field paths. If another change was saved first, review the newer revision's diff and select **Reload text**; your draft remains below the editor for copying.

Use **New** on a list to create an entity from a template. New loops start paused; review the trigger and prompt before selecting **Resume**. **Delete** shows the entity name and affected loops or projects before confirmation. Removing a label declaration does not delete labels on GitHub.

Each detail page has **History**, with revision numbers, actors, times, and messages. Select a revision to see the before-and-after text as a diff. **Revert** creates a revision restoring every entity in the selected revision, with an optional message. A later change to an affected entity can prevent a revert. **Configuration > History** lists all revisions and links to the changed entities.

Accepted revisions apply live to new work; running attempts continue. A change that needs a restart or fails worker preflight is refused with the reason. For command-line editing and bulk changes, use [`usine config edit`, `import`, `export`, and `log`](/reference/configuration/cli/#configuration-revisions). Files are an import and export format; editing the original files does not change the stored configuration.
