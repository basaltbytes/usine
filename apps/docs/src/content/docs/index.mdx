## Loop files

usine stores loops and agents in its database, with a revision for each configuration change. Markdown files are their import and export format. A loop's frontmatter sets which issues or pull requests open a run, whether you approve each run, and which agent does the work. Its body is the agent's task. This loop runs usine on its own repository:

```markdown title="usine/start-dev (export format)" wrap
---
trigger:
  on: issue
  if: >-
    item.state == "OPEN" &&
    item.labels.nodes.exists(label, label.name == "ready-for-agent") &&
    !item.closedByPullRequestsReferences.nodes.exists(pr, pr.state == "OPEN")
selector:
  repos: [basaltbytes/usine]
approval: required
step: implement
agent: developer
---

Use the repository's `tackle-issue` skill to complete issue #{{ item.number }}: {{ item.title }}.

Before editing, remove `ready-for-agent` from the issue and add `agent-in-progress`. Complete the issue through a non-draft pull request whose body closes the issue. Do not merge it. Once the pull request is ready, remove `agent-in-progress` from the issue and add `ready-for-review` to the pull request.

If work cannot continue, add a comment to the issue that states the exact blocker. Do not add a workaround that changes the issue's scope.
```

Create the [bootstrap files](/guides/#create-the-instance-folder) before the first `usine up`, which imports them as revision 1. Later starts ignore those configuration files. Use [`usine config`](/reference/configuration/config/) to edit the stored configuration.

You approve, follow, and steer the work in a local web UI.
