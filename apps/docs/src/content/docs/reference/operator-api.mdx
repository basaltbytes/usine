The operator API reads instance state, manages configuration, and operates runs. This reference renders the committed [OpenAPI 3.1 document](/openapi.json). For the contract of a running instance, request `GET /api/openapi.json` from that instance. The schema endpoint is public and contains no instance configuration or credentials.

## Authentication

Send an instance token as `Authorization: Bearer <token>`. Browser clients can use the `usine_session` cookie; writes with a session also require `X-Usine-CSRF`. See [Sign in](/guides/sign-in/) for browser sessions, and [Create a device token](/guides/create-a-device-token/) for token issuance. The document marks health, sign-in, and schema operations as public. `GET /api/auth/session` returns effective permissions as `{permission, scope}` grants. Roles and token ceilings both limit access; a forbidden operation returns HTTP 403. Lists include only projects with read access.

Viewer requires `read`, operator adds `operate`, and maintainer adds `maintain` on a project. Instance `admin` grants all operations, including membership, bindings, workers, settings, and upgrades. Project resource handlers check the target project in addition to the route requirement. See [roles and scopes](/reference/access/#roles).

`POST /api/tokens` accepts a name and scopes and returns the secret once. `PUT /api/tokens/:id/scopes` changes an owned token's ceiling. Neither accepts scopes wider than the caller's effective permissions. Token listing includes scopes. The local admin token has instance admin permissions and a null member; its writes are attributed to `local admin`.

Use HTTPS through a reverse proxy for remote access. Browser requests must use an origin accepted by the instance. URL-encode path parameters, including slashes in repository names and qualified loop names. An acknowledgement from an asynchronous action means the server accepted the request; read the corresponding status to learn its outcome.

## Paths and versions

Paths use `/api/...`. The schema’s `info.version` is `unversioned`; `GET /api/version` returns the running release string. The public `/api/ready` endpoint returns 200 after startup recovery and 503 while startup is incomplete.

The reference covers the operator HTTP API, including sign-in, members, and tokens. Static UI assets and the separate signature-verified GitHub webhook listener are outside this contract.

## Polling summaries and detail

`GET /api/overview` returns project and board summaries with item titles, states, labels, counts, and identities. Its runs use `RunSummaryView` and its attempts use `AttemptSummaryView`. `GET /api/desk` uses the same summary types for running, stalled, and recent runs.

Read `GET /api/runs/:runId` for the run's task, result message, each attempt's task, event payload, and transcript. The task endpoint, `GET /api/projects/:owner/:repository/tasks/:item`, also returns full run and attempt records. The board's **Run again** action reads run detail before submitting the saved task and agent.

## Change notices and conditional reads

`GET /api/changes` returns `text/event-stream`. A `change` event contains `{revision, reset, changes}`, where each change has a `kind` and an entity `id`. Notice kinds include projects, items, runs, attempts, workers, configuration, attention, navigation, and activity. Notices contain identifiers only. Event IDs increase monotonically. Send `Last-Event-ID` to resume; a `reset: true` notice requests fresh reads when the cursor is unavailable. The server retains 256 notices per effective permission set and sends heartbeats every 15 seconds.

Successful operator JSON reads return an `ETag`. Authentication and setup responses use `Cache-Control: no-store`. Send it as `If-None-Match`; an unchanged response returns HTTP 304 with no body. Validators are private to the authenticated representation.

`X-Usine-View: shell` on `/api/overview` returns navigation and compact task identities. `X-Usine-View: attention` returns attention entries. `X-Usine-View: board` on `/api/projects/:project` returns settled lane counts; read their cards from `/api/projects/:project/lanes/:lane/items?offset=0` in pages of 50. `X-Usine-View: task` on a repository task read returns the first 25 runs and `runsTotal`; read subsequent pages from `/api/projects/:owner/:repository/tasks/:item/runs?offset=25`. Page responses include `nextOffset`, which is null at the end. `GET /api/workers` returns worker configuration and slot usage.

The board representation includes `board.cardedItemKeys` for every linked item with a card, including cards in unloaded pages. Use these keys to distinguish runs without cards from runs on paginated cards.
